# 长任务进度反馈：生成器 + QThread + Signal

> **适用场景**：界面上点一下，后台要跑 10 秒到几分钟的活（解压、解析、批量转换、爬取），需要**逐条**把进度打到日志区，界面不能卡死，最好还能取消。
> 一句话架构：**业务写成生成器，线程消费生成器，信号把消息送回主线程。**

## 1. 为什么是这三个东西配合

| 组件 | 解决什么 | 不这么做会怎样 |
|---|---|---|
| 生成器 `yield` | 业务代码每做完一步就「吐」一条进度，不用知道 GUI 存在 | 业务里到处 `print()` 或回调 UI，无法单元测试、无法复用 |
| `QThread` | 耗时活离开主线程 | 界面「未响应」，进度条一格都动不了 |
| `Signal` | 子线程把消息安全送到主线程 | 子线程直接碰控件 → 随机崩溃 |

**解耦点在第 1 条**：`process_xxx()` 是个纯 Python 生成器，脱离界面也能 `next()` 一步步跑，日志、进度条、命令行三个壳子共用一个业务函数。

## 2. 业务侧：把流程写成生成器

约定 `yield (is_error, message)`，最后 `return` 一个总结果：

```python
import os
import traceback

def process_file(src_path, output_dir):
    work_dir = os.path.join(output_dir, "unpacked")

    try:
        yield False, "开始解压"
        if src_path.endswith((".tar.gz", ".zip")):
            unzip_archive(src_path, work_dir)
        else:
            yield True, "不支持的文件类型"
            return False
        yield False, "解压完成"

        yield False, "开始解析"
        yield from parse_config(work_dir)     # 委托子生成器，进度照常透传
        yield False, "解析完成"
        return True

    except Exception:
        yield True, f"主程序错误:\n{traceback.format_exc()}"
        return False
```

| 语法 | 作用 |
|---|---|
| `yield x` | 暂停并交出一个值，函数变成生成器 |
| `yield from gen` | 委托另一个生成器，把它的 `yield` 全部透传上来（嵌套步骤不用手动转） |
| `return x` | 结束生成器，值存进 `StopIteration.value`，正好拿来当最终结果 |

生成器的行为可以直接在命令行验证，不需要开界面：

```python
def gen():
    yield "A"
    yield "B"
    return "Done"

g = gen()
next(g)   # 'A'
next(g)   # 'B'
next(g)   # StopIteration，e.value == 'Done'
```

## 3. 线程侧：消费生成器

```python
from collections.abc import Generator
from PySide6.QtCore import QThread, Signal

class WorkThread(QThread):
    update_signal = Signal(bool, str)     # (是否错误, 文本)
    finished_signal = Signal(str)

    def __init__(self, func, *args, **kwargs):
        super().__init__()
        self.func = func                  # 函数对象，不是调用结果
        self.args = args
        self.kwargs = kwargs
        self._running = True

    def run(self):
        gen = self.func(*self.args, **self.kwargs)
        if not isinstance(gen, Generator):        # 普通函数：直接当结果
            self.finished_signal.emit(str(gen))
            return

        try:
            while self._running:
                item = next(gen)                  # 取一条进度（可能抛异常）
                self.update_signal.emit(*item)    # 拆成两个参数再发
        except StopIteration as e:                # 正常结束
            self.finished_signal.emit(str(e.value))
        except Exception:                         # 兜底：生成器内部没接住的异常
            self.update_signal.emit(True, traceback.format_exc())
            self.finished_signal.emit("异常终止")

    def stop(self):
        self._running = False
```

**为什么要 `emit(*item)`**：`Signal(bool, str)` 声明了两个独立参数，而 `yield` 出来的是一个元组。直接 `emit(item)` 会报 `TypeError: argument 1 has unexpected type 'tuple'`。

| 写法 | 传入内容 | 是否合法 |
|---|---|---|
| `emit(item)` | 一个二元组 | 不合法，签名不匹配 |
| `emit(*item)` | 解包成两个参数 | 合法，等价于 `emit(False, "解压完成")` |

信号签名按需声明，不强求 `(bool, str)`：

```python
progress = Signal(int)                   # 只报百分比
detail   = Signal(str, int)              # 文本 + 百分比
```

## 4. UI 侧：连接与生命周期

```python
class MainWindow(QMainWindow):
    def __init__(self):
        super().__init__()
        self.log = QTextEdit()
        self.btn = QPushButton("开始处理")
        self.btn.clicked.connect(self.start_task)
        # ... 布局省略
        self.worker = None

    def start_task(self):
        if self.worker and self.worker.isRunning():   # 防连点重入
            return
        self.log.clear()
        self.worker = WorkThread(
            process_file,                 # 函数对象，不加括号
            self.file_edit.text(),
            self.output_edit.text(),
        )
        self.worker.update_signal.connect(self.on_update)
        self.worker.finished_signal.connect(self.on_finished)
        self.worker.start()

    def on_update(self, is_error, message):
        prefix = "[ERROR]" if is_error else "[INFO]"
        self.log.append(f"{prefix} {message}")

    def on_finished(self, result):
        self.log.append(f"[DONE] {result}")
```

三条硬规矩：

1. **传函数对象，不传调用结果**。写 `WorkThread(process_file("./in", "./out"))` 会在主线程立刻执行 `process_file`，拿到的是生成器对象，但主线程已卡住、信号也没人发；
2. **worker 存成 `self.worker`**。临时实例会被 GC 回收，线程跟着挂掉；
3. **所有控件操作只在槽函数里**。`emit()` 保证槽在主线程执行，这是唯一安全通道。

## 5. 完整流程

```mermaid
graph TD
    A[用户点击开始] --> B[创建 WorkThread(func, args)]
    B --> C[worker.start 进入子线程]
    C --> D[gen = func(*args)]
    D --> E[while _running: next(gen)]
    E --> F[emit 解包后发信号]
    F --> G[主线程 槽函数 更新界面]
    E --> H{生成器结束}
    H -- 是 --> I[StopIteration.value]
    I --> J[finished_signal 显示结果]
    H -- 否 --> E
```

对照着看每一步发生在哪：

| 步骤 | 位置 | 动作 |
|---|---|---|
| 1 | 子线程 | `process_file(...)` 返回生成器对象（此时一行代码都没执行） |
| 2 | 子线程 | `next(gen)` 执行到第一个 `yield` |
| 3 | 子线程 | `emit(*item)` 把消息投进主线程事件队列（不阻塞） |
| 4 | 主线程 | 槽函数被调用，`QTextEdit.append` |
| 5 | 子线程 | 循环直到 `StopIteration`，取 `.value` 发完成信号 |

每一条日志，都是生成器「吐」出来的一条 `yield`。

## 6. 两个必须知道的边界

### 6.1 取消是协作式的，杀不掉阻塞调用

`_running = False` 只在**下一次循环**生效。如果当前正卡在 `unzip_archive()` 这种同步 IO 里，`stop()` 调完也不会立刻返回，要等这一行自己跑完。

要真正能中断，只有两条路：

- 在底层函数里加停止标记轮询（`if stop_flag: return`），适合自己写的循环；
- 把活丢到独立**进程**（`multiprocessing` / `QProcess`），直接终止进程。

别指望 `QThread.terminate()`——它会在任意位置掐断，锁和文件句柄都来不及释放，容易把输出文件写坏。

### 6.2 异常边界决定 `finished_signal` 会不会丢

`next(gen)` 抛出的异常如果没有任何人接住，会直接冲出 `run()`，线程静默结束，界面永远等不到「完成」。两种兜底方式任选其一，推荐**都用**：

- 业务异常在生成器内部统一 `yield True, msg` 再 `return`（日志可控、错误信息完整）；
- `run()` 的 `while` 外面再包一层 `except Exception`，接住漏网的（示例里已加）。

## 7. 最小可运行示例（PySide6）

```python
import sys
import time
import traceback
from collections.abc import Generator

from PySide6.QtWidgets import (
    QApplication, QMainWindow, QWidget, QVBoxLayout,
    QPushButton, QTextEdit
)
from PySide6.QtCore import QThread, Signal

def mock_process():
    yield False, "开始模拟任务..."
    time.sleep(1)
    yield False, "步骤 1 完成"
    time.sleep(1)
    yield False, "步骤 2 完成"
    time.sleep(1)
    yield False, "步骤 3 完成"
    return "任务成功"

class WorkThread(QThread):
    update_signal = Signal(bool, str)
    finished_signal = Signal(str)

    def __init__(self, func, *args, **kwargs):
        super().__init__()
        self.func, self.args, self.kwargs = func, args, kwargs
        self._running = True

    def run(self):
        gen = self.func(*self.args, **self.kwargs)
        if not isinstance(gen, Generator):
            self.finished_signal.emit(str(gen))
            return
        try:
            while self._running:
                self.update_signal.emit(*next(gen))
        except StopIteration as e:
            self.finished_signal.emit(str(e.value))
        except Exception:
            self.update_signal.emit(True, traceback.format_exc())
            self.finished_signal.emit("异常终止")

    def stop(self):
        self._running = False

class MainWindow(QMainWindow):
    def __init__(self):
        super().__init__()
        self.setWindowTitle("生成器进度演示")
        self.resize(600, 400)

        self.btn = QPushButton("开始处理")
        self.log = QTextEdit()
        self.btn.clicked.connect(self.start_task)

        layout = QVBoxLayout()
        layout.addWidget(self.btn)
        layout.addWidget(self.log)
        container = QWidget()
        container.setLayout(layout)
        self.setCentralWidget(container)

        self.worker = None

    def start_task(self):
        if self.worker and self.worker.isRunning():
            return
        self.log.clear()
        self.worker = WorkThread(mock_process)
        self.worker.update_signal.connect(self.on_update)
        self.worker.finished_signal.connect(self.on_finished)
        self.worker.start()

    def on_update(self, is_error, message):
        self.log.append(("[ERROR] " if is_error else "[INFO] ") + message)

    def on_finished(self, result):
        self.log.append(f"[DONE] {result}")

if __name__ == "__main__":
    app = QApplication(sys.argv)
    win = MainWindow()
    win.show()
    sys.exit(app.exec())
```

## 8. PyQt5 / PySide6 对照

| 项目 | PyQt5 | PySide6 |
|---|---|---|
| 信号类 | `from PyQt5.QtCore import pyqtSignal` | `from PySide6.QtCore import Signal` |
| 启动 | `app.exec_()` | `app.exec()` |
| 枚举 | `Qt.AlignCenter`（不带作用域） | `Qt.AlignmentFlag.AlignCenter` |
| `exec` 传参 | `emit(*item)` 完全相同 | 同左，这套解包逻辑不用改 |

迁移只需改导入和这两个调用，生成器、线程消费、信号连接一行不动。

## 9. 陷阱清单

| 坑 | 后果 | 正解 |
|---|---|---|
| `WorkThread(process_file(a, b))` 传调用结果 | 主线程立刻执行，界面卡死、信号全无 | 传函数对象 + 参数分开传 |
| 子线程里直接 `log.append()` | 随机崩溃 | 走 `Signal` |
| `emit(item)` 传元组 | `TypeError: unexpected type 'tuple'` | `emit(*item)` |
| 生成器内部不接异常，`run()` 也不接 | 线程静默死掉，界面永远停在最后一条 | 内部 `yield True, msg` + `run()` 外层兜底 |
| 以为 `stop()` 能立刻停 | 卡在阻塞 IO 时毫无反应 | 明确是协作式取消；要真中断得加轮询标记或用进程 |
| 用 `terminate()` 强杀线程 | 文件写坏、句柄泄漏 | 不用，改协作式或进程方案 |
| `while True:` 没有 `_running` | 用户点了取消也停不下来 | 循环条件带标志位 |
| 每次点击都新建 worker 不保存引用 | 多个线程并行写同一控件 | `self.worker` + `isRunning()` 判重 |

## 10. 速查

```text
业务：def process(): yield (is_err, msg) ... return result
     子步骤用 yield from 透传
线程：class W(QThread): s = Signal(bool, str)
     run(): gen = func(*args); while _running: s.emit(*next(gen))
     except StopIteration as e: finished.emit(str(e.value))
界面：点击里建 worker → connect → start；槽里改控件
取消：_running=False 只在下一次循环生效，阻塞调用杀不掉
```
