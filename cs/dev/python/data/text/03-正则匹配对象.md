# 正则匹配对象 re.Match

> **适用场景**：不只是判断"有没有匹配"，而是要从文本里**取出具体片段**——日志里的时间戳、配置里的编号、URL 里的参数。
> **核心认知**：`re.Match` 是"提取结果"的统一接口，不是"是否匹配"的布尔值。

## 一、基本概念

- `re.search()`、`re.match()`、`re.fullmatch()` 等函数在**匹配成功时**返回一个 `re.Match` 对象；
- 匹配失败时返回 `None`；
- `re.Match` 是正则引擎封装的**匹配结果容器**，承载匹配过程的全部结构化信息。

核心认知：**正则表达式 = 模式匹配 + 结构提取**。`re.Match` 是"提取结果"的统一接口，而非"是否匹配"的布尔值。

## 二、核心属性与方法

| 方法 / 属性 | 作用 | 抽象意义 |
|---|---|---|
| `.group()` 或 `.group(0)` | 返回**完整匹配的文本** | 捕获"整个模式命中"的原始内容 |
| `.group(n)` | 返回第 `n` 个**捕获组**的内容（n ≥ 1） | 捕获组由括号 `()` 定义，用于提取子匹配片段 |
| `.groups()` | 返回**所有捕获组**组成的元组 | 多个子提取结果的集合 |
| `.span()` | 返回匹配在源字符串中的 `(start, end)` 位置 | 定位匹配的精确字符范围，支持上下文分析 |
| `.start()` / `.end()` | 分别返回匹配的起始与结束偏移量 | 精确文本定位，可用于编辑、高亮、分段处理 |
| `.groupdict()` | 若使用命名组，返回 `{name: value}` 字典 | 支持语义化字段提取，提升可维护性 |

> 关键原则：括号 `()` 在正则中不是语法装饰，而是**提取指令**。每个括号定义一个"捕获单元"，编号从 1 开始按左括号顺序排列。

## 三、捕获组（Capturing Group）

- **定义**：正则中用 `(...)` 包裹的部分；
- **作用**：从完整匹配中"提取"出关心的**子部分**；
- **编号规则**：按左括号出现的先后顺序编号，`group(1)` 是第一个，依此类推；
- **层级无关**：嵌套括号不影响编号顺序，始终按从左到右的出现顺序。

## 四、命名组（Named Group）—— 推荐做法

- 语法：`(?P<name>...)`
- 作用：为捕获组赋予**语义名称**，替代数字编号；
- 访问方式：`match.group("name")` 或 `match.groupdict()["name"]`。

优势：

1. 不依赖括号顺序，模式微调时代码更鲁棒；
2. 可读性与可维护性更好；
3. 适合复杂模式或多组提取场景。

> 生产系统中优先使用命名组，避免因模式调整导致 `group(1)` 指向错误。

## 五、安全使用规范

```python
import re

match = re.search(pattern, text)
if match:
    extracted = match.group(n)        # 或 match.group("name")
else:
    extracted = None                  # 无匹配时的默认处理
```

> **永远先判断 `match is not None`，再调用 `.group()` 等方法。** 否则 `None` 上取属性会触发 `AttributeError`。

## 六、场景速查

| 场景 | 推荐做法 |
|---|---|
| 仅需判断是否匹配 | `if re.search(...):` |
| 需提取子串 | `group(n)` 或 `group("name")` |
| 多个子提取 | `groups()` 或 `groupdict()` |
| 模式复杂、易变 | 强制使用命名组 `(?P<name>...)` |
| 任何提取场景 | 必须先做 `if match:` 判空检查 |

## 一句话总结

`re.Match` 是正则匹配过程的**结构化输出接口**——它不是"是否匹配"的布尔值，而是"匹配了什么、在哪里、怎么分"的元信息容器，是正则从"文本搜索"迈向"结构化信息提取"的关键桥梁。
