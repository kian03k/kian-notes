# self、`__iter__` 与迭代器协议

围绕三个常见困惑展开：`self` 到底是什么、为什么父类和子类都有 `__iter__`、父类里 `raise NotImplementedError` 的意义。

**核心结论**：父类和子类各有一个 `__iter__` 不是重复初始化，而是"父类定义接口 + 子类实现逻辑"的**方法重写（Override）**。

## 一、self：当前实例对象的引用

```python
class NICAdapter(InputAdapter):
    def __init__(self, input_dir: str):
        self.inspect_dir = os.path.join(input_dir, "inspect")
```

`self` 是 Python **自动传入**的第一个参数，代表**当前实例对象本身**。当你写：

```python
adapter = NICAdapter("/data")
```

Python 底层做了类似下面的事：

```python
adapter = NICAdapter.__new__(NICAdapter)   # 创建一个空对象
NICAdapter.__init__(adapter, "/data")      # 调用 __init__，把 adapter 作为 self 传入
```

所以 `self.inspect_dir = ...` 等价于 `adapter.inspect_dir = ...`。

- `self` 就是那个你创建的实例对象本身；
- 它是 Python 实现"对象状态"和"方法绑定"的核心机制；
- 每个对象都有自己独立的 `self`，互不干扰。

## 二、`__iter__`：迭代协议的入口

`for` 循环不是"魔法"，靠**协议（Protocol）**工作：

```python
for x in obj:
    print(x)
```

底层等价于：

```python
iterator = obj.__iter__()   # ← 这里调用 __iter__
while True:
    try:
        x = iterator.__next__()
        print(x)
    except StopIteration:
        break
```

- 定义了 `__iter__` 的类就是**可迭代对象（Iterable）**；
- `__iter__` 必须返回一个**迭代器（Iterator）**——通常是其自身逻辑的生成器：

```python
def __iter__(self):
    for entry in os.listdir(...):
        ...
        yield entry, content   # yield 使函数返回生成器对象（生成器就是一种迭代器）
```

## 三、父类和子类都有 `__iter__`：继承 + 方法重写

```python
class InputAdapter:
    def __iter__(self):
        raise NotImplementedError          # 父类：只定义"接口"

class NICAdapter(InputAdapter):
    def __iter__(self):                    # 子类：实现具体逻辑
        for entry in ...:
            yield ...
```

| 概念 | 说明 |
|---|---|
| 继承 | `NICAdapter(InputAdapter)` 表示子类自动拥有父类的所有方法和属性 |
| 方法重写（Override） | 子类定义了与父类**同名的方法** → Python 使用子类的实现，忽略父类的 |
| 抽象方法 | `raise NotImplementedError` 是一种"契约"：子类必须重写这个方法 |

**底层机制：方法查找顺序（MRO）**。执行 `for x in adapter` 时，Python 按以下顺序找 `__iter__`：

1. 在 `NICAdapter` 中找 → 找到，用子类的实现；
2. 没找到 → 去 `InputAdapter` 中找 → 会命中父类的 `raise NotImplementedError`；
3. 还没找到 → 去 `object` 中找 → 没有 → 报错。

所以子类的 `__iter__` 完全覆盖了父类的——父类的只是"占位符"。

## 四、NotImplementedError：抽象基类的契约

父类写 `raise NotImplementedError` 是**抽象基类（ABC）**的经典模式，目的是**强制子类实现接口**：

```python
class InputAdapter:
    def __iter__(self):
        raise NotImplementedError("子类必须实现 __iter__ 方法")

    def count_files(self) -> int:
        raise NotImplementedError("子类必须实现 count_files 方法")
```

典型场景：有多种采集方式（`NICAdapter` 读 `inspect/` 目录、`ZIPAdapter` 读压缩包、`DBAdapter` 读数据库），希望所有适配器都支持统一的遍历方式，但具体怎么读由子类决定：

```python
for filename, content in adapter:
    process(content)
```

如果子类忘了重写，运行时立刻报错，而不是悄悄出错：

```python
class BadAdapter(InputAdapter):
    pass  # 没有写 __iter__

adapter = BadAdapter()
for x in adapter:   # ← 运行时报错
    ...
# NotImplementedError: 子类必须实现 __iter__ 方法
```

这是设计模式中的**模板方法模式**——父类定义骨架，子类填细节。作用类似 Java 的 `interface` 或 C++ 的纯虚函数。

## 五、`__xxx__`：魔法方法（Dunder Methods）

`__xxx__` 方法不是主动调用的，而是**Python 解释器在特定时机自动调用**的"语言层面契约"：

| 语法 | 底层调用 |
|---|---|
| `for x in obj` | `obj.__iter__()` |
| `len(obj)` | `obj.__len__()` |
| `obj[0]` | `obj.__getitem__(0)` |
| `obj + other` | `obj.__add__(other)` |
| `print(obj)` | `obj.__str__()` |

## 六、一次 for 循环的完整底层流程

```python
adapter = NICAdapter("/data")   # 1. 创建对象
for name, content in adapter:   # 2. for 循环触发 __iter__
    print(name)
```

| 步骤 | Python 内部做了什么 |
|---|---|
| 1 | `NICAdapter("/data")` → `__new__` 创建对象 → `__init__` 初始化 → `self.inspect_dir = "/data/inspect"` |
| 2 | `for ... in adapter` → 检查 `adapter` 是否有 `__iter__` → 按 MRO 找到 `NICAdapter.__iter__` |
| 3 | 调用 `NICAdapter.__iter__(self)` → 执行生成器函数 → 返回一个**生成器对象**（迭代器） |
| 4 | `for` 循环调用 `生成器.__next__()` → 执行到 `yield entry, content` → 返回一个元组 |
| 5 | 每次 `yield` 暂停函数并把值交给 for 循环；下次迭代从 yield 后继续执行 |
| 6 | 目录遍历完 → 生成器抛出 `StopIteration` → for 循环结束 |

整个过程**没有一次性读取所有文件**，而是逐个按需读取——这就是生成器的内存优势。

## 七、抽象基类的价值与多态

| 作用 | 说明 |
|---|---|
| 定义接口 | 告诉所有子类："必须能被 for 循环遍历，必须能统计文件数" |
| 防止误用 | 忘写 `__iter__` 时运行时立刻报错 |
| 统一调用方式 | 无论哪个子类，调用方式都一样：`for x in adapter` |
| 支持多态 | 函数参数声明为父类类型，传任意子类都行 |

```python
def analyze_adapter(adapter: InputAdapter):
    print(f"共 {adapter.count_files()} 个设备")
    for name, content in adapter:
        if name == "MISSING":
            print(f"⚠️ {content} 缺失")
        else:
            print(f"✅ {name} 有 {len(content)} 字符")

# 传任意子类都可以：
analyze_adapter(NICAdapter("/data/nic"))
analyze_adapter(ZIPAdapter("/data/archive.zip"))
```

这就是面向对象的"多态"：**同一个接口，不同实现**。

## 八、总结

| 问题 | 答案 |
|---|---|
| `self` 是什么？ | 当前对象实例的引用，Python 自动传入，代表"正在操作的这个具体对象" |
| 为什么有两个 `__iter__`？ | 一个父类定义接口、一个子类实现逻辑；子类覆盖父类 |
| 是初始化两次吗？ | 不是。初始化只发生一次（`__init__`），`__iter__` 是方法调用 |
| `__iter__` 是什么？ | Python 迭代协议方法，`for` 循环靠它工作；必须返回迭代器（如生成器） |
| 为什么 `raise NotImplementedError`？ | 运行时强制提醒"你忘了实现这个方法"——是设计模式，不是错误 |
| 生成器为什么高效？ | 不一次性加载所有数据，每次 `yield` 一个，内存占用恒定 |

**类比**：父类 `InputAdapter` 是"快递接口标准"（必须能遍历包裹、能数包裹数），`NICAdapter`/`ZIPAdapter` 是不同的快递公司（各自决定从哪取包裹）。你写 `for package in express_company: deliver(package)` 时，不需要知道具体是哪家——只要遵守接口就能用。

**动手验证**：

1. `print(type(adapter.__iter__()))` → 输出 `<class 'generator'>`；
2. 故意不写 `__iter__`，观察 `NotImplementedError` 报错；
3. 自己写一个 `ZIPAdapter` 继承 `InputAdapter`，用 `zipfile.ZipFile` 读取文件，体会接口统一的好处。
