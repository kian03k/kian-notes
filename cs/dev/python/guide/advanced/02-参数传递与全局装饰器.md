# 参数传递 args/kwargs 与全局装饰器

## 1. *args 与 **kwargs 是什么

| 语法 | 作用 | 存储类型 | 参数名是否固定 |
|---|---|---|---|
| `*args` | 捕获所有**位置参数**（不带关键字） | 元组 | 可改名，惯例用 `args` |
| `**kwargs` | 捕获所有**关键字参数**（`key=value`） | 字典 | 可改名，惯例用 `kwargs` |

```python
def my_func(*args):
    print("args 是元组：", args)

my_func(1, 2, 3)
# 输出：args 是元组： (1, 2, 3)

def my_func2(**kwargs):
    print("kwargs 是字典：", kwargs)

my_func2(a=1, b=2, c=3)
# 输出：kwargs 是字典： {'a': 1, 'b': 2, 'c': 3}
```

关键澄清：

- **"位置参数"与代码位置、行数无关**，指调用时按顺序传递的参数：`add(1, 2)` 中 1 对应 `a`、2 对应 `b`；用关键字传参则顺序无关：`add(b=2, a=1)`。
- **真正起作用的是符号 `*` 和 `**`**，它们告诉 Python"把剩余的位置/关键字参数打包起来"；`args`、`kwargs` 只是变量名，可以自定义：

```python
def my_func(*my_positional, **my_keyword):
    print("位置参数：", my_positional)  # (10, 20)
    print("关键字参数：", my_keyword)   # {'name': 'Alice', 'age': 30}

my_func(10, 20, name="Alice", age=30)
```

但约定俗成使用 `args`/`kwargs`，可读性更好。

## 2. 为什么装饰器必须用它们

装饰器的包装函数需要**适配被装饰函数的任意参数**：

```python
def my_decorator(func):
    def wrapper(*args, **kwargs):   # 接收任意参数
        print("装饰器开始执行")
        return func(*args, **kwargs)  # 原样传递给原函数
    return wrapper

@my_decorator
def add(a, b):
    return a + b

add(1, 2)        # 位置参数
add(b=3, a=2)    # 关键字参数
add(4, b=5)      # 混合参数
```

无论 `add` 需要什么形式的参数，`wrapper` 都能正确接收并透传，保证装饰器对任意函数通用。

## 3. 使用场景

### 3.1 定义可变参数的函数

```python
def log_all(*args, **kwargs):
    print("位置参数:", args)
    print("关键字参数:", kwargs)

log_all(1, 2, name="Alice", age=30)
# 位置参数: (1, 2)
# 关键字参数: {'name': 'Alice', 'age': 30}
```

### 3.2 固定参数与可变参数混用

```python
def example(a, b, *args, **kwargs):
    print("固定参数 a:", a)
    print("固定参数 b:", b)
    print("额外位置参数 args:", args)
    print("关键字参数 kwargs:", kwargs)

example(1, 2, 3, 4, name="Bob", age=25)
# 固定参数 a: 1
# 固定参数 b: 2
# 额外位置参数 args: (3, 4)
# 关键字参数 kwargs: {'name': 'Bob', 'age': 25}
```

### 3.3 调用时解包（反向操作）

定义时 `*`/`**` 是**打包**，调用时则是**解包**：

```python
def add(a, b):
    return a + b

args = (1, 2)
kwargs = {"a": 1, "b": 2}

add(*args)      # 等价于 add(1, 2)
add(**kwargs)   # 等价于 add(a=1, b=2)
```

| 语法 | 含义 | 例子 |
|---|---|---|
| `*args` | 将元组/列表解包为位置参数 | `f(*(1,2))` → `f(1, 2)` |
| `**kwargs` | 将字典解包为关键字参数 | `f(**{"a": 1})` → `f(a=1)` |
| `*` | 解包可迭代对象 | `[*[1,2,3]]` → `[1,2,3]` |
| `**` | 解包字典（合并） | `{**{"x":1}, **{"y":2}}` → `{"x":1,"y":2}` |

## 4. 注意事项

- **参数顺序**：`*args` 必须在 `**kwargs` 之前，否则语法错误：

```python
def invalid(**kwargs, *args):   # 错误！
    pass
```

- **关键字参数不能重复**：`func(a=1, a=2)` 报错；`func(1, b=2)` 正确（a 按位置、b 按关键字）。
- 同一参数不能既按位置又按关键字传递两次。

## 5. 全局装饰器：统一封装项目通用逻辑

为全项目定义统一的全局装饰器（异常处理、日志、性能监控）是推荐实践，符合 DRY 原则：

- **减少重复代码**：通用逻辑集中在装饰器，不在每个函数里重复。
- **统一行为**：全项目的异常、日志处理方式一致。
- **易于扩展**：改逻辑只需改装饰器一处。

### 5.1 组织方式：集中到独立模块

建议放到 `utils/decorators.py`，全项目导入：

```python
# utils/decorators.py
import logging
import time
from functools import wraps

# 统一异常处理装饰器（支持传入 logger）
def log_exception(logger=logging.getLogger(__name__)):
    def decorator(func):
        @wraps(func)
        def wrapper(*args, **kwargs):
            try:
                return func(*args, **kwargs)
            except Exception as e:
                logger.error(f"在 {func.__name__} 中发生异常: {str(e)}", exc_info=True)
                return None  # 根据需求调整返回值
        return wrapper
    return decorator

# 性能监控装饰器
def timeit(logger=logging.getLogger(__name__)):
    def decorator(func):
        @wraps(func)
        def wrapper(*args, **kwargs):
            start = time.time()
            result = func(*args, **kwargs)
            elapsed = time.time() - start
            logger.info(f"函数 {func.__name__} 耗时: {elapsed:.4f} 秒")
            return result
        return wrapper
    return decorator

# 进出日志装饰器
def log_entry_exit(func):
    @wraps(func)
    def wrapper(*args, **kwargs):
        logging.info(f"进入函数 {func.__name__}")
        result = func(*args, **kwargs)
        logging.info(f"退出函数 {func.__name__}")
        return result
    return wrapper
```

### 5.2 在项目中使用

```python
# example_module.py
import logging
from utils.decorators import log_exception, timeit

logger = logging.getLogger(__name__)

@log_exception(logger=logger)
@timeit(logger=logger)
def risky_function():
    # 可能抛出异常或耗时的操作
    pass

@log_exception()   # 使用默认 logger
def another_risky_function():
    pass
```

### 5.3 进阶：重试装饰器与组合使用

```python
def retry(max_retries=3, delay=1):
    def decorator(func):
        @wraps(func)
        def wrapper(*args, **kwargs):
            for _ in range(max_retries):
                try:
                    return func(*args, **kwargs)
                except Exception:
                    time.sleep(delay)
            raise Exception(f"尝试 {max_retries} 次失败")
        return wrapper
    return decorator

# 组合多个装饰器
@log_exception()
@timeit()
@retry(max_retries=2)
def critical_function():
    pass
```

### 5.4 注意事项

1. **装饰器顺序从下到上**：`@a` 在 `@b` 之上时，实际执行 `func = a(b(func))`，即下面的先包裹。
2. **性能开销**：装饰器带来轻微开销，高频调用的函数需权衡必要性。
3. **避免过度使用**：装饰器只服务于通用逻辑，单个装饰器只做一件事，逻辑过于复杂会降低可读性。
4. **日志配置一致**：装饰器内的 `logging.getLogger(__name__)` 应与项目日志配置保持一致。

## 6. 总结

- `*args`/`**kwargs` 是 Python 处理可变参数的核心语法：定义时打包（元组/字典），调用时解包。
- 符号 `*`、`**` 是关键，参数名可自定义但建议遵循惯例。
- 装饰器中必须使用它们，才能透明适配任意被装饰函数。
- 全局装饰器集中放在独立模块，统一异常/日志/性能监控，是提升项目一致性和可维护性的标准做法。
