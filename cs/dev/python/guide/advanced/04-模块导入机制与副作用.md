# 模块导入机制与副作用

> **适用场景**：`import` 一个模块时莫名跑了日志、连了数据库、发了网络请求；`import` 特别慢；两个模块互相 import 直接崩；包里的脚本单独运行报 `ModuleNotFoundError`；改了模块代码却不生效。
> 一句话结论：**导入即执行**。所有「导入的怪事」都是这一条的推论。

## 1. 本质：加载模块 = 把文件从头跑一遍

`import mymodule` 会找到 `mymodule.py`，在**当前进程**里完整执行一遍：顶层赋值、函数与类的定义（只定义不调用）、以及所有模块级语句（`print`、`open`、请求、日志配置……）。

```python
# mymodule.py
print("I AM EXECUTED ON IMPORT!")     # 导入时就打印
config = open("config.txt").read()    # 导入时就读了文件
def get_data():                       # 只定义，不执行
    return config
```

```python
# main.py
from mymodule import get_data    # 上面的 print 和 open 已经跑完了
result = get_data()              # 此时才进函数体
```

**关键认知**：`from mod import func` ≠「只导入函数」。它同样加载整个模块，只是把指定名字绑到当前命名空间。所以「我明明只 import 了一个函数，它却把整个文件都执行了」不是 bug，是语义。

## 2. 缓存：同一进程内只执行一次

模块加载后会存进 `sys.modules`，后续 `import` 只做字典查找，不再执行。

```python
import sys
import mymodule          # 第一次：执行整个文件
import mymodule          # 第二次：直接取缓存
print("mymodule" in sys.modules)    # True
```

三条推论：

- **跨进程不共享**：另起一个 Python 进程，一切重来；
- **单例效果**：模块级变量天然是进程内单例，适合放配置、连接池；
- **改代码要重启**：交互环境里改了模块文件，`import` 不会重新加载，得 `importlib.reload()`（见 §7）。

## 3. 副作用长什么样

| 顶层写法 | 导入时会发生什么 | 风险 |
|---|---|---|
| `print(...)` / 写日志 | 每次都往输出里塞一行 | 日志重复、无法关掉 |
| `open()` / 读配置 | 文件不存在直接抛异常 | 整个程序起不来，栈还指在「导入」上 |
| `requests.get()` / 连库 | 导入即发请求 | 网络慢、超时导致 import 卡住 |
| 启动线程 / 定时器 | 导入即开始跑 | 无法控制启停，测试难隔离 |
| 修改全局状态（`os.environ`、日志配置） | 影响全进程 | 与调用方的配置互相覆盖 |

判断标准很简单：**这段代码「只在程序启动时该跑一次」，还是「每次用的时候都该跑」？** 后者就不该待在顶层。

## 4. 方案：把副作用挪进函数（惰性加载）

配置、连接、大文件这类东西，第一次用到时再读，读完缓存住：

```python
# safe_module.py
from pathlib import Path

_cache: dict[str, str] = {}

def load_config(filename: str) -> str:
    if filename not in _cache:
        _cache[filename] = Path(filename).read_text(encoding="utf-8")
    return _cache[filename]

def get_rules(path: str) -> list[str]:
    return parse(load_config(path))        # 首次调用才读文件
```

```python
# main.py
from safe_module import get_rules
rules = get_rules("rules.json")     # 导入时零开销
```

`read_text()` 必须显式 `encoding="utf-8"`——默认走系统 locale，Windows 上是 GBK，中文配置必乱码（详见 [[01-pathlib速查]]）。

只需要「算一次」的场景，也可以直接上 `functools.lru_cache`：

```python
from functools import lru_cache

@lru_cache(maxsize=None)
def get_conn():
    return create_connection("db.conf")    # 第一次调用建连，之后复用
```

上面这种「模块级 `dict` 缓存」做大了就是一套进程内缓存：复合 key、线程锁、容量上限、失效一致性都要自己管。完整机制与边界见 [[01-进程内备忘缓存]]。

## 5. 方案：入口控制 `if __name__ == "__main__"`

模块被导入时 `__name__` 是模块名（如 `"mymodule"`）；被直接运行时是 `"__main__"`。

```python
# mymodule.py
def run():
    ...

if __name__ == "__main__":     # 只有 python mymodule.py 才执行
    run()
```

这一句挡住的正是「模块顶层的测试代码、调试打印、命令行参数解析」——有它在，模块既能被 import，又能当脚本跑。

### 包内脚本怎么跑：`-m` 与直接运行的区别

假设目录是：

```text
project/
├── pkg/
│   ├── __init__.py
│   ├── core.py
│   └── main.py
└── run.py
```

`pkg/main.py` 里写了 `from pkg.core import work` 或 `from .core import work`：

| 运行方式 | `sys.path[0]` | 结果 |
|---|---|---|
| `python pkg/main.py` | `project/pkg` | `ModuleNotFoundError: No module named 'pkg'`；相对导入报 `attempted relative import with no known parent package` |
| `python -m pkg.main` | 当前目录 `project` | 正常，`__package__` 被正确设置 |

**结论**：包内带相对导入的模块，一律在项目根目录用 `python -m pkg.main` 跑；`python pkg/main.py` 只适合没有任何包内导入的独立脚本。

## 6. 方案：循环导入

`a.py` 导入 `b.py`，`b.py` 又导入 `a.py`，典型的报错是：

```text
ImportError: cannot import name 'foo' from partially initialized module 'a'
(most likely due to a circular import)
```

原因是执行到一半的模块里还没有 `foo` 这个名字。三种解法，按推荐顺序：

**① 重构：把公共部分抽到第三个模块（最干净）**

```text
a.py ──┐
b.py ──┴──> common.py     # 两边都依赖 common，不再互指
```

**② 局部导入：把 import 挪进函数（改动最小）**

```python
# a.py
def build():
    from b import helper      # 调用时才导入，此时 b 早已加载完
    return helper()
```

**③ 延迟注解：只是类型标注需要，就不必真导入**

```python
from __future__ import annotations
from typing import TYPE_CHECKING

if TYPE_CHECKING:             # 只给类型检查器看，运行时跳过
    from b import B

def handle(x: "B") -> None: ...
```

注意 `import a.b as m` 这种形式不会立刻报错，但会在运行到一半时才炸，比直接报错更难查——看到「两个模块互相引用」这个结构就该改。

## 7. 调试导入问题

| 想知道 | 手段 |
|---|---|
| 模块到底有没有被加载 | 模块顶部 `print(f"Loaded: {__file__}")`，或查 `sys.modules` |
| 哪一步导入最慢 | `python -X importtime main.py 2> import.log`，看累计耗时排序 |
| 这行 import 走了哪条路径 | `import mymodule; print(mymodule.__file__)` |
| 环境里装的是哪个包 | `python -c "import pkg; print(pkg.__file__, pkg.__version__)"` |
| 改完代码想立即生效 | 交互环境下 `importlib.reload(mymodule)`；**生产代码不要依赖 reload**，重启进程最可靠 |

`-X importtime` 对「启动慢」特别有效，输出里能直接看到哪个第三方包占了几百毫秒（常见大户：`matplotlib`、`pandas`、`tensorflow`）。

## 8. 陷阱清单

| 坑 | 后果 | 正解 |
|---|---|---|
| 认为 `from m import f` 只加载 `f` | 顶层副作用照样执行 | 记住「导入即执行」，把副作用挪进函数 |
| 模块顶层读配置 / 连数据库 | 文件缺失时整个程序起不来，错误栈指向 import | 惰性加载 + 显式 `init()` |
| 顶层启动线程 / 定时器 | 导入即跑，无法停止，测试互相污染 | 由调用方显式启动 |
| 两个模块互相 import | `partially initialized module` | 抽公共模块 / 函数内导入 / `TYPE_CHECKING` |
| 包内脚本用 `python pkg/main.py` | 相对导入报错 | 用 `python -m pkg.main` |
| 交互环境改完模块直接再 import | 不生效，还是旧代码 | `importlib.reload()` 或重启 |
| `open()` 不写 encoding | Windows 上中文乱码 | 一律 `encoding="utf-8"` |
| 以为导入一次就全局共享 | 换进程/换线程池子进程后状态丢失 | 需要跨进程共享就落文件或走显式传参 |

## 9. 速查

```text
导入 = 执行整个文件；from m import f 也一样
缓存 = sys.modules，同进程只执行一次
防副作用：顶层只放定义，I/O 与连接包进函数（lru_cache 缓存结果）
入口：if __name__ == "__main__":  → 被导入时不执行
包内运行：python -m pkg.main（不要 python pkg/main.py）
循环导入：抽公共模块 > 函数内 import > TYPE_CHECKING
诊断：python -X importtime main.py ｜ mod.__file__
```
