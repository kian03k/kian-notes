# 02 标准框架：多模块项目的日志方案（团队标准）

> 目标：**配置一次，全项目生效**。任何业务模块只写固定两行，日志自动带模块名，同时输出控制台和文件。本篇是多套旧日志方案笔记收敛后的终版。

## 1. 效果预览

任意业务模块里：

```python
logger.info("用户 张三 尝试登录")
```

输出（自动带时间、级别、来源文件和行号）：

```
2025-04-05 15:30:00-INFO-user.py:12 - 用户 张三 尝试登录
```

## 2. 终版配置文件：Src/utils/log_format.py（复制即用）

```python
# Src/utils/log_format.py
import logging
from pathlib import Path

# 统一日志格式
FORMAT = "%(asctime)s-%(levelname)s-%(filename)s:%(lineno)d - %(message)s"
DATEFMT = "%Y-%m-%d %H:%M:%S"

# 明确公共接口，防止 from ... import * 污染
__all__ = ["setup_logging"]


def setup_logging(log_file: str = "./log.log", level: int = logging.DEBUG) -> None:
    """全局日志初始化，整个进程只调用一次。

    - 控制台输出 DEBUG 及以上
    - 文件输出 INFO 及以上（追加模式，不覆盖历史日志）
    - handlers.clear() 防止 Jupyter / 热重载场景重复输出
    """
    log_path = Path(log_file)
    log_path.parent.mkdir(parents=True, exist_ok=True)

    formatter = logging.Formatter(FORMAT, datefmt=DATEFMT)

    stream_handler = logging.StreamHandler()
    stream_handler.setLevel(logging.DEBUG)
    stream_handler.setFormatter(formatter)

    file_handler = logging.FileHandler(log_path, encoding="utf-8")  # 默认追加；确需每次清空才加 mode='w'
    # 生产环境建议换轮转（见 03-进阶配置）：
    # from logging.handlers import RotatingFileHandler
    # file_handler = RotatingFileHandler(log_path, maxBytes=10*1024*1024, backupCount=5, encoding="utf-8")
    file_handler.setLevel(logging.INFO)
    file_handler.setFormatter(formatter)

    root_logger = logging.getLogger()
    root_logger.setLevel(level)
    root_logger.handlers.clear()      # 清掉旧 handler，防重复注册
    root_logger.addHandler(stream_handler)
    root_logger.addHandler(file_handler)
    # 可选：压制第三方库刷屏（见 03-进阶配置）
    # logging.getLogger("urllib3").setLevel(logging.WARNING)


if __name__ == "__main__":
    # 本地验证配置是否生效
    setup_logging("./test.log")
    logging.getLogger(__name__).info("配置正常")
```

## 3. 入口与业务模块

```python
# main.py（项目入口）
from Src.utils.log_format import setup_logging

setup_logging("./log.log")        # 全项目唯一一次日志初始化

import logging
logger = logging.getLogger(__name__)
logger.info("应用程序启动成功")

from Src.utils.data_processor import run
run()
```

```python
# Src/utils/data_processor.py（任意业务模块，固定两行）
import logging
logger = logging.getLogger(__name__)   # 标准写法，每个模块都要有

def run():
    logger.info("开始处理数据")
    logger.error("数据库连接失败")
```

推荐项目结构：

```
your_project/
├── main.py                     # 入口：第一件事 setup_logging()
├── Src/
│   ├── __init__.py
│   └── utils/
│       ├── log_format.py       # 唯一日志配置文件
│       ├── data_processor.py   # 业务模块：固定两行写法
│       └── api_client.py
└── log.log                     # 自动生成
```

## 4. 原理：为什么是 `logging.getLogger(__name__)`

`__name__` 是 Python 内置变量：直接运行的文件为 `"__main__"`，被导入的文件为模块路径（如 `Src.utils.data_processor`）。

| 写法 | 用的 logger | 日志里显示的名字 |
| --- | --- | --- |
| `logging.info("...")` | root logger | 全部显示 `__main__`，分不清来源 |
| `logger = logging.getLogger(__name__)` 后用 `logger.info` | 模块自己的 logger | 显示模块路径，一眼定位 |

logger 按名字构成一棵树：`root → Src → Src.utils → Src.utils.data_processor`。子 logger 默认不带 handler，日志沿树**传播**给 root 的 handler 统一输出——这就是"模块只写两行、配置只做一次"能成立的原因。

root 方案做不到、模块 logger 能做到的：

```python
# 对某个子树单独调级别，改配置即可，不动业务代码
logging.getLogger("Src.api").setLevel(logging.DEBUG)
```

## 5. 为什么不用其他写法

### vs basicConfig

| 维度 | basicConfig | setup_logging() |
| --- | --- | --- |
| 重复调用 | root 已有 handler 时静默忽略（3.8+ 需 `force=True` 才重置） | `handlers.clear()` 安全重置 |
| 控制台/文件分开控级 | 不支持 | 各 handler 独立 `setLevel` |
| 路径/级别参数化 | 硬编码 | `setup_logging("./test.log")` |
| 单元测试友好度 | 弱 | 显式函数，可传测试路径单独验证 |

结论：单文件脚本用 basicConfig（见 [[01-快速上手]]），多模块项目用 setup_logging()。

### vs MyLogging 自研单例类

| 自研写法 | 问题 |
| --- | --- |
| `from my_logging import MyLogging; my_logger = MyLogging()` | 重复造轮子，非官方标准，团队看不懂 |
| 所有模块共用一个 logger | 无法区分来源、无法按模块控级 |
| 自己封装 debug/info/error 方法 | mock 困难，遮蔽官方能力 |

logging 模块本身按名字全局注册 logger（天然单例），不需要再包一层。旧 MyLogging 方案已弃用，迁移步骤见 [[04-特殊场景手册]]。

## 6. 方案演进对照（原笔记共 4 代）

| 代 | 方案 | 结论 |
| --- | --- | --- |
| 1 | 到处写 `logging.basicConfig()` | 不推荐：重复配置、不可控 |
| 2 | log_config.py 顶层代码配置 | 可用但隐式：import 即产生副作用 |
| 3 | log.py 顶层配置 + `import *` 激活 | 同上，且 `import *` 被团队规范禁止 |
| 4 | **setup_logging() 显式初始化（本篇）** | 采用：显式、参数化、可测试 |

## 7. 团队规范与常见误区

| 误区 | 正确做法 |
| --- | --- |
| 在每个模块里写 basicConfig / addHandler | 配置只在 log_format.py，入口调一次 |
| 直接用 `logging.info()` | 固定两行：`import logging` + `getLogger(__name__)` |
| 用 print 打调试信息 | `logger.debug()`，生产环境自动关闭 |
| `@Singleton` 包装日志类 | 直接 getLogger，天然单例 |
| `except: pass` 吞异常 | `logger.error(...)` 后 `raise`（见 04） |
| 只记 error 不记 info | 正常流程也记，才能看出系统是否健康 |
| 日志不带模块名 | format 必含 `%(name)s` 或 `%(filename)s:%(lineno)d` |

**口诀：一个配置、一个入口、一个 logger、一个模块名。**
