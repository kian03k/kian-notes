## 场景 1：try-except 里怎么记日志

标准姿势：**记下来，别装没事，告诉上一级（error + raise）**。

```python
def take_money(amount):
    logger.info(f"尝试取款 {amount} 元")
    try:
        if amount > 50:
            raise Exception("余额不足！")
        logger.info(f"取款成功！{amount} 元已取出")
    except Exception as e:
        logger.error(f"取款失败：{e}")   # 1. 记录错误
        raise                           # 2. 继续抛出，让上层感知，而不是假装没事
```

| 代码 | 含义 |
| --- | --- |
| `try` 之前 `logger.info` | 记录正常流程，排查时能还原"出错前发生了什么" |
| `logger.error(...)` | 在日志里记下"出错了、为什么错" |
| `raise` | 不能只记不报——上层需要感知失败（回滚、提示用户） |

三个典型反例：

```python
except:
    pass                    # 反例1：吞掉异常，程序假装没事，问题无从排查
print("出错了！")            # 反例2：没时间戳、没级别、关不掉
# 反例3：只写 error 不写 info —— 无从判断系统平时是否正常运行
```

> 需要完整堆栈时，用 `logger.exception("取款失败")` 代替 `logger.error`，它会自动附带 traceback（标准库能力，此处补充）。

## 场景 2：日志重复输出 / Jupyter 与热重载

**现象**：同一条日志打两遍；Jupyter 反复运行 cell 后越打越多。

**原因**：root logger 上叠了多份 handler（多次初始化、重新 import、重复调用配置）。

**解决**：初始化前清空旧 handler（02 的 setup_logging 已内置）：

```python
root_logger.handlers.clear()
root_logger.addHandler(stream_handler)
root_logger.addHandler(file_handler)
```

用 basicConfig 的场景，Python 3.8+ 可用：

```python
logging.basicConfig(..., force=True)   # 先移除已有 root handler 再重新配置
```

> 注意：对 root logger 设置 `propagate = False` 没有作用（root 没有父级可传播），旧笔记中的这一条是无效配置，已删除。

## 场景 3：MyLogging 自研类迁移到标准库

旧代码用单例类封装日志，问题：无法区分来源、无法按模块控级、难以 mock。

五步迁移：

| 步骤 | 操作 |
| --- | --- |
| 1 | 新建 `Src/utils/log_format.py`，复制 02 的 setup_logging() |
| 2 | 入口文件改为 `setup_logging()`（替换原来的 `import MyLogging`） |
| 3 | 全局搜索 `from ... my_logging import MyLogging`，全部删除 |
| 4 | 全局搜索 `my_logger = MyLogging()`，全部删除 |
| 5 | 正则替换 `my_logger\.(\w+)` → `logger.\1`，每个文件顶部补固定两行 |

检查哪些文件还没迁移：

```python
# check_log_migration.py
import os

def find_old_log_usage():
    for root, _, files in os.walk("Src"):
        for file in files:
            if file.endswith(".py"):
                path = os.path.join(root, file)
                with open(path, "r", encoding="utf-8") as f:
                    content = f.read()
                    if "MyLogging" in content or "my_logger" in content:
                        print(f"未迁移: {path}")
                        for line in content.splitlines():
                            if "MyLogging" in line or "my_logger" in line:
                                print(f"  > {line.strip()}")

find_old_log_usage()
```

## 场景 4：单元测试中 mock 日志

业务模块用标准两行写法后，logger 是模块的全局变量，直接 patch 该模块的 logger 即可：

```python
from unittest.mock import patch

def test_payment_error():
    with patch("Src.utils.payment.logger") as mock_logger:   # patch 目标模块的 logger
        pay(-10)                                             # 被测函数
        mock_logger.error.assert_called_once()               # 断言记了 error
```

> 自研 MyLogging 类把 logger 封装在实例内部，很难这样替换——这是"不要自造轮子"的又一个理由。
