# 路径逻辑放在哪：config.py 全局配置 vs 参数传入

> **适用场景**：多子系统项目里，每个模块都要拿到项目根目录去定位输入/输出文件。此时该写一个全局 `config.py`、让每个函数都收路径参数、还是两种都要，是个绕不开的架构选择。
> 结论先说：**混合方案**——`config.py` 提供默认值，函数签名留一个可覆盖的参数口子。
> 目录本身怎么算出来（`__file__` / `sys.executable` / `sys._MEIPASS`）见 [[04-脚本路径定位与打包资源]]，本篇只谈「算出来的路径该放哪管」。

## 1. 先排除伪问题：性能不是理由

每个模块都调一次「判断 frozen + 算 dirname」，代价小到可以忽略：

```python
import os
import sys
import timeit

def get_base_dir():
    if getattr(sys, "frozen", False):
        return os.path.dirname(sys.executable)
    return os.path.dirname(os.path.dirname(os.path.dirname(__file__)))

t = timeit.timeit(get_base_dir, number=100_000)
print(f"10 万次调用耗时: {t:.4f} 秒")            # 通常 < 0.05 秒
print(f"单次调用耗时: {t / 100_000 * 1000:.6f} 毫秒")   # 约 0.0005 毫秒
```

单次约 **0.5 微秒**，100 个模块各调一次总耗时不足 0.05 毫秒，完全无感知。**性能不构成放弃这种写法的理由**，真正要解决的是重复与维护成本：

| 问题 | 说明 |
|---|---|
| 重复代码 | 上百个文件各写一遍，违反 DRY |
| 维护成本高 | 路径调整（如 `Output` → `data`）要改上百个文件 |
| 易出错 | 手写时少一层 `dirname`，路径就错 |
| 测试困难 | 无法在单元测试中替换路径 |

## 2. 方案 A：全局 `config.py` 统一管理

### 2.1 在项目根目录创建 config.py

```python
# config.py —— 放项目最顶层，与各子系统目录同级
import os
import sys

def get_base_dir():
    """统一获取项目根目录（开发 / 打包环境）"""
    if getattr(sys, "frozen", False):
        # 打包后：sys.executable 是 .exe，其所在目录即项目根目录
        return os.path.dirname(sys.executable)
    # 开发环境：config.py 就在项目根目录
    return os.path.dirname(os.path.abspath(__file__))

BASE_DIR = get_base_dir()          # 模块只加载一次，预先算好
INPUT_PATH = os.path.join(BASE_DIR, "data", "input_data.csv")
OUTPUT_DIR = os.path.join(BASE_DIR, "data", "output")
```

后续要加 `LOG_DIR`、`TEMP_DIR`、`CONFIG_FILE` 也都在这里加。若各子系统共用同一个输出目录，就只定义一份，不必按子系统拆。

### 2.2 业务模块只 import，不再写路径逻辑

```python
# subsys_a/step_01.py
import os
import pandas as pd
from config import INPUT_PATH, OUTPUT_DIR

def process_a():
    os.makedirs(OUTPUT_DIR, exist_ok=True)
    if not os.path.exists(INPUT_PATH):
        raise FileNotFoundError(INPUT_PATH)
    df = pd.read_csv(INPUT_PATH, encoding="utf-8-sig")
    # ... 处理逻辑
    df.to_csv(os.path.join(OUTPUT_DIR, "result_a.csv"), index=False, encoding="utf-8-sig")
```

```python
# main.py
from subsys_a.step_01 import process_a
from subsys_b.step_01 import process_b

def main():
    process_a()        # 无需传参
    process_b()

if __name__ == "__main__":
    main()
```

### 2.3 打包时把 config.py 带上

```python
# app.spec
a = Analysis(
    ["main.py"],
    pathex=[],
    binaries=[],
    datas=[
        ("data", "data"),
        ("config.py", "."),      # 关键：把 config.py 放到打包根目录
    ],
    # ...
)
```

或命令行：

```bash
pyinstaller --add-data "data;data" --add-data "config.py;." main.py
```

打包后 `config.py` 与 `main.exe` 同目录，`get_base_dir()` 依然正确工作。

### 2.4 优势与代价

| 优势 | 说明 |
|---|---|
| 零重复代码 | 各模块不再写路径逻辑 |
| 一处修改全局生效 | 改 `config.py` 一行即可 |
| 路径集中管理 | 便于 CI/CD 校验与统一处理 |
| 打包完全兼容 | `sys.executable` 逻辑不变 |
| 性能无损 | 模块只加载一次，`BASE_DIR` 是常量 |

代价：函数依赖全局状态（与 config 耦合），跨环境复用和单元测试稍麻烦。

## 3. 方案 B：路径作为参数传入

```python
# main.py
from subsys_a.step_01 import process_a
from subsys_b.step_01 import process_b

def main():
    input_path = r"D:\MyTool\data\input_data.csv"
    output_dir = r"D:\MyTool\data\output"

    process_a(input_path, output_dir)
    process_b(input_path, output_dir)
```

```python
# subsys_a/step_01.py
import os
import pandas as pd

def process_a(input_path: str, output_dir: str):
    os.makedirs(output_dir, exist_ok=True)
    if not os.path.exists(input_path):
        raise FileNotFoundError(input_path)
    df = pd.read_csv(input_path, encoding="utf-8-sig")
    # ... 处理逻辑
    df.to_csv(os.path.join(output_dir, "result_a.csv"), index=False, encoding="utf-8-sig")
```

函数不依赖外部状态，是纯函数：可移植、可测试、可复用，是专业库的标准写法。代价是每次调用都要写路径，冗长易错。

## 4. 两方案逐项对比

| 维度 | 参数传入 | config.py 全局配置 | 胜出方 |
|---|---|---|---|
| 代码复用性 | 每次调用重复写路径 | 所有函数自动读取 | config |
| 维护成本 | 路径变更要改所有调用点 | 改 config 一行全局生效 | config |
| 测试友好性 | 可 mock 任意路径，非常灵活 | 需要 monkey patch，较麻烦 | 参数 |
| 可移植性 | 纯函数，不依赖外部状态 | 依赖全局变量 | 参数 |
| 打包兼容性 | 无论路径从哪来都接受 | 打包后依然有效 | 平手 |
| 开发体验 | 每次调用都写路径，冗长易错 | 一行调用搞定 | config |
| 团队协作 | 新人要记「每个函数传哪两个参数」 | 行为一致、约定清晰 | config |
| 扩展性 | 天然支持不同输入/输出目录 | 靠环境变量 / 配置文件扩展 | 参数 |
| 高内聚 | 不依赖外部状态 | 依赖全局状态 | 参数 |
| 低耦合 | 与路径解耦，可独立复用 | 耦合了路径逻辑 | 参数 |

没有绝对优劣，看项目类型：

| 项目类型 | 推荐方案 | 原因 |
|---|---|---|
| 内部工具、固定结构、一次打包长期运行 | config.py | 路径不变、调用频繁，写一次用一百次 |
| 可复用库、要被其他项目调用、要单测、路径动态 | 参数传入 | 纯函数可测试、可移植、可插拔 |
| 既要灵活测试又要方便部署 | 混合方案 | config 作默认值，允许传参覆盖 |

## 5. 推荐：混合方案（参数优先，config 为默认）

### 5.1 函数支持传参，默认从 config 读取

```python
# subsys_a/step_01.py
import os
import pandas as pd
from config import INPUT_PATH, OUTPUT_DIR      # 默认值

def process_a(input_path: str = None, output_dir: str = None):
    # 没传参数就用 config 里的默认值
    input_path = input_path or INPUT_PATH
    output_dir = output_dir or OUTPUT_DIR

    os.makedirs(output_dir, exist_ok=True)
    if not os.path.exists(input_path):
        raise FileNotFoundError(f"输入文件不存在：{input_path}")

    df = pd.read_csv(input_path, encoding="utf-8-sig")
    # ... 业务逻辑

    result_path = os.path.join(output_dir, "result_a.csv")
    df.to_csv(result_path, index=False, encoding="utf-8-sig")
    print(f"生成：{result_path}")
```

### 5.2 main.py 按需传参

```python
# main.py
from subsys_a.step_01 import process_a
from subsys_b.step_01 import process_b

def main():
    # 正常部署：什么都不传，用 config.py 里的路径
    process_a()
    process_b()

    # 开发 / 测试时：临时指定路径
    # process_a(input_path=r"D:\test\input.csv", output_dir=r"D:\test\output")

if __name__ == "__main__":
    main()
```

### 5.3 单元测试直接传临时路径

```python
# test_step_01.py
import os
import tempfile
from subsys_a.step_01 import process_a

def test_process_a():
    with tempfile.TemporaryDirectory() as tmpdir:
        test_input = os.path.join(tmpdir, "input.csv")
        test_output = os.path.join(tmpdir, "output")

        with open(test_input, "w", encoding="utf-8-sig") as f:
            f.write("id,name,value\n1,示例,100")

        process_a(input_path=test_input, output_dir=test_output)

        assert os.path.exists(os.path.join(test_output, "result_a.csv"))
```

### 5.4 为什么混合方案最优

| 优势 | 说明 |
|---|---|
| 默认行为简单 | 绝大多数场景一行调用，自动工作 |
| 测试无压力 | 传临时路径即可，不污染全局 config |
| 调试灵活 | 临时改路径传参即可，不改代码 |
| 部署稳定 | 打包后 config.py 依然生效 |
| 为 CLI 做准备 | 命令行参数天然走「传参」通道 |

## 6. 落地后的项目结构

```text
MyTool/                          ← 打包后根目录（或开发根目录）
├── main.py                      ← 入口，调用各子系统
├── config.py                    ← 统一路径配置（核心）
├── data/
│   ├── input_data.csv
│   └── output/
├── subsys_a/
│   ├── __init__.py
│   └── step_01.py               ← 只 import config
├── subsys_b/
│   ├── __init__.py
│   └── step_01.py
└── app.spec                     ← PyInstaller 配置
```

落地步骤：新建 `config.py` → 删除各模块内路径逻辑 → 统一为 `from config import ...`（或改成带默认参数的函数签名）→ spec 加 `--add-data "config.py;."` → 开发与打包环境各验证一遍。**不需要改任何业务逻辑。**

## 7. 进阶：环境变量覆盖与 CLI

### 7.1 环境变量覆盖（不同环境用不同数据目录）

```python
# config.py
import os
import sys

def get_base_dir():
    if getattr(sys, "frozen", False):
        return os.path.dirname(sys.executable)
    return os.path.dirname(os.path.abspath(__file__))

BASE_DIR = get_base_dir()

# 支持环境变量覆盖路径（开发 / 测试时方便）
OUTPUT_ROOT = os.getenv("APP_OUTPUT_DIR", os.path.join(BASE_DIR, "data"))
INPUT_PATH = os.path.join(OUTPUT_ROOT, "input_data.csv")
DEFAULT_OUTPUT_DIR = os.path.join(OUTPUT_ROOT, "output")
```

开发时切换目录：

```bash
set APP_OUTPUT_DIR=D:\myproject\test_output
python main.py
```

这样测试、部署、CI 都能灵活切换数据目录，不改代码。

### 7.2 命令行工具（CLI）

```bash
python main.py --input D:\test\input.csv --output D:\test\out
```

要做 CLI 就必须走「参数传入」通道，而混合方案的函数签名天然支持——CLI 解析出的路径作为参数传入即可，config 只是缺省值：

```python
# main.py（补充示例）
import argparse

def parse_args():
    parser = argparse.ArgumentParser()
    parser.add_argument("--input", default=None, help="输入文件路径")
    parser.add_argument("--output", default=None, help="输出目录")
    return parser.parse_args()

def main():
    args = parse_args()
    process_a(input_path=args.input, output_dir=args.output)
```

## 8. 陷阱清单

| 陷阱 | 后果 | 正解 |
|---|---|---|
| 用 `or` 处理空字符串默认值 | `output_dir=""` 也会被吃掉换成默认值，用户显式传空无法生效 | 需要区分时用 `if output_dir is None:` |
| `config.py` 里 `from config import ...` 循环引用 | config 自己 import 了自己所在包的业务模块就成环 | config 只依赖 `os`/`sys`，不 import 业务模块 |
| 把 config.py 打进包却不加 `--add-data` | 打包后 `ImportError: No module named config` | spec 里显式加 `("config.py", ".")` |
| 打包后 config.py 在 `_MEIPASS` 里而非 exe 旁 | 用户改配置改不动（临时目录，退出即失） | 可写配置走 exe 同级，只读规则才进包 |
| 开发时 `BASE_DIR` 多层 `dirname` 数错 | 路径指到项目外一层 | 数清目录层级；或让 config.py 待在根，只用一层 |
| 路径写死成开发机绝对路径（方案 B 常见） | 换台机器就崩 | 传参时由调用方从 config / CLI 提供 |
| 混合方案里函数内部再读 `os.getcwd()` 兜底 | 静默引入运行目录依赖 | 默认值只来自 config，不回退 CWD |

## 9. 速查

> 内部工具一次打包长期用 → `config.py`；要给别的项目调用 / 写单测 → 传参；两头都要 → 函数签名默认 `None`，内部 `or` 到 config 值。路径集中到 `config.py` 一处，业务代码只 `import`，永不自己算目录；打包记得 `--add-data "config.py;."`。
