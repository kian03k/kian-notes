# 目录体积分析（谁最占地方）

> **适用场景**：磁盘要满、仓库瘦身前，先跑一遍看清哪个目录最大。

## 1. 方案：递归累加 + 人类可读单位

```python
import os

def dir_size(path):
    total = 0
    for parent, _dirs, files in os.walk(path):
        for name in files:
            try:
                total += os.path.getsize(os.path.join(parent, name))
            except OSError:      # 断开/权限不足的文件跳过
                continue
    return total

def human(n):
    for unit in ("B", "KB", "MB", "GB", "TB"):
        if n < 1024:
            return f"{n:.1f}{unit}"
        n /= 1024
    return f"{n:.1f}PB"
```

## 2. 方案：列出子目录排行

```python
def top_subdirs(path, top=15):
    rows = []
    for name in os.listdir(path):
        p = os.path.join(path, name)
        if os.path.isdir(p):
            rows.append((dir_size(p), name))
    rows.sort(reverse=True)
    for size, name in rows[:top]:
        print(f"{human(size):>10}  {name}")
```

## 3. 陷阱清单

| 坑 | 后果 | 对策 |
|---|---|---|
| 不捕获 `OSError` | 遇到断链/无权限文件整个脚本崩 | 单文件级 `try/except OSError` |
| 用 `sum(getsize(...))` 一次性读 | 权限异常让整个 sum 失败 | 循环里逐个加 |
| 忽略硬链接/稀疏文件 | 体积虚高 | 严格场景按 inode 去重 |
| 对系统盘全扫 | 耗时极长且触发权限问题 | 只扫指定目录 |
| 结果只打印字节数 | 看不懂 | 换算成 KB/MB/GB |

> 在 WSL 里扫 `/mnt/c` 会走 9p 文件系统，极慢——扫 Windows 盘宁可开 Windows 侧的 python。
