# 02 · 仓库与远程连接

> 第 2 环。目标：无论手上是「空目录 + 空远端」还是「已有代码 + 远端已有内容」，都能一次性把本地和远端接上，并且不丢历史。

## 2.1 先判断你在哪种情形

动手前先回答两个问题，路径完全不同：

| | 远端是空的 | 远端已有提交 |
| --- | --- | --- |
| **本地已有 Git 仓库**（有 `.git/`） | 情形 B | 情形 D（最易出错） |
| **本地是普通目录**（无 `.git/`） | 情形 A | 情形 C |

```bash
ls -a | grep .git                 # 判断本地是否已有仓库
git remote -v                     # 有仓库时看远端配了没
git ls-remote origin              # 远端有没有内容（有输出＝非空）
```

## 2.2 情形 A：空目录 → 空远端（全新项目）

```bash
mkdir myproj && cd myproj
git init -b main                  # -b 直接指定初始分支名，避免 master/main 混乱
# 先写 .gitignore，再放代码
git add .
git commit -m "chore: init project"
git remote add origin git@github.com-personal:kian03k/myproj.git
git push -u origin main
```

`-u`（= `--set-upstream`）建立本地分支与远端分支的追踪关系，**只需第一次**。之后 `git push` / `git pull` 不用带参数。

## 2.3 情形 B：本地已有仓库 → 空远端

代码已经在本地提交过，只是没接远端：

```bash
git remote add origin git@github.com-personal:kian03k/existing.git
git push -u origin main
```

如果远端默认分支叫 `master` 而本地叫 `main`（或反之），有两种处理：

```bash
# 做法1：把本地分支改名，与远端对齐（推荐，一次解决）
git branch -M main

# 做法2：显式推送并建立追踪
git push -u origin main:master
```

## 2.4 情形 C：普通目录 → 远端已有内容

比如远端已经用 README 初始化过，本地是另一份代码。**不要直接 `git push`**，会被拒（`fetch first`）。

```bash
git init -b main
git remote add origin git@github.com-personal:kian03k/myproj.git
git fetch origin
git reset --soft origin/main      # 把本地 HEAD 挪到远端提交上，工作区文件一个不动
git status                        # 现在所有本地文件都是「新增」，按需增删
git add .
git commit -m "feat: 导入本地已有代码"
git push
```

`reset --soft` 是关键：它只移动分支指针，不碰工作区，所以本地文件不会丢。用 `reset --hard` 会直接覆盖掉你的文件。

## 2.5 情形 D：本地已有仓库 → 远端已有内容

两边各有一段互不相关的历史。Git 默认拒绝合并：

```bash
git pull origin main
# fatal: refusing to merge unrelated histories
```

两种决策，取决于哪边的历史更值得留：

| 目标 | 做法 |
| --- | --- |
| 保留远端历史，本地改动作为新提交叠上去 | `git pull origin main --allow-unrelated-histories`，解决冲突后提交 |
| 保留本地历史，远端历史直接丢弃 | `git push --force-with-lease origin main`（**确认远端没有别人在协作**） |

选第二种前，先 `git branch backup-$(date +%Y%m%d)` 给当前状态留个后路。

## 2.6 克隆：拿到别人的仓库

```bash
git clone git@github.com-personal:kian03k/kian-notes.git
git clone git@github.com-personal:kian03k/kian-notes.git mydir   # 指定目录名
git clone --depth 1 <url>                                        # 只取最新一次提交，体积小、无历史
```

克隆后检查：

```bash
git remote -v          # origin 指向是否正确
git branch -vv         # 是否有上游追踪
```

仓库在 WSL、需要从 Windows 访问时，别用 `/mnt/d` 或 `\\wsl$` 跨系统读写（9p 文件系统，git 操作会慢十倍以上）。要么整个在 WSL 内操作，要么把仓库放在 Windows 侧。

## 2.7 远端管理速查

| 目的 | 命令 |
| --- | --- |
| 查看远端 | `git remote -v` |
| 新增远端 | `git remote add <name> <url>` |
| 改地址（如 HTTPS 换 SSH） | `git remote set-url origin git@...` |
| 删除远端 | `git remote remove <name>` |
| 看远端分支实况（不落地） | `git ls-remote --heads origin` |
| 重命名远端 | `git remote rename origin upstream` |

多远端（fork 贡献场景）见 [[08-开源协作Fork模式]]：`origin` 指自己的 fork，`upstream` 指原项目。
