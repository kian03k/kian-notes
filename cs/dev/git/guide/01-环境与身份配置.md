# 01 · 环境与身份配置

> Git 全链路第 1 环。目标：让本机具备「能提交、能认证、能在 Windows/WSL 双环境下不打架」的最小条件。做完这一章，后面所有命令都能跑通。

## 1.1 安装与版本

```bash
git --version          # 建议 ≥ 2.28（git init -b 支持）、≥ 2.23（git switch 支持）
```

| 环境 | 安装方式 | 备注 |
| --- | --- | --- |
| Windows | 官网 Git for Windows，或 `winget install Git.Git` | 自带 Git Bash，装完 PATH 就绪 |
| WSL2 Ubuntu | `sudo apt install git` | 与 Windows 侧是**两套独立 Git**，配置也各自独立 |

> 双环境要点：Windows 与 WSL 的 `~/.gitconfig`、`~/.ssh` 互不相通。同一个仓库如果两边都操作，两边的用户名、密钥都要配一遍。

## 1.2 身份：user.name 与 user.email

提交记录里的作者信息来自这两项，**配错会导致 GitHub 认不出提交是你**（提交头像不显示、贡献图不亮）。

```bash
# 全局（默认值，适用于个人项目）
git config --global user.name "kian"
git config --global user.email "你的GitHub绑定邮箱"

# 仓库级（覆盖全局，适用于工作仓库用另一个身份）
cd /path/to/repo
git config user.name "work-account"
git config user.email "work@company.com"
```

验证：

```bash
git config --global --list
git config --list --show-origin   # 带来源文件，排查「为什么这项生效了」
```

配置文件位置见 [[git配置位置及命令解释]]。

## 1.3 换行符：双环境最容易踩的坑

Windows 用 CRLF，Linux/macOS 用 LF。不统一会出现「一行没改，整个文件显示已修改」。

| 场景 | 推荐配置 |
| --- | --- |
| Windows 仓库（团队全在 Windows） | `git config --global core.autocrlf true` |
| WSL / Linux | `git config --global core.autocrlf input` |
| 跨平台协作 | 两个环境都设 `core.autocrlf false`，改由仓库内 `.gitattributes` 统一：`* text=auto` |

已经乱了怎么办见 [[行分割符修复]]，假阳性的其他成因见 [[Git Detects Changes]]。

## 1.4 认证：为什么本项目一律走 SSH

HTTPS 方式每次推送都要凭据，且在公司网络/受限网络下 443 可能被重置或拦截。SSH 配一次长期有效，因此本库统一约定：**远端地址一律用 `git@` 开头**。

### 1.4.1 生成密钥

```bash
ssh-keygen -t ed25519 -C "kian03k@example.com" -f ~/.ssh/id_ed25519_kian03k
```

- `-t ed25519`：现代默认选择，密钥短、签名快。与 RSA 的详细对比见 [[ssh密钥与多账号]]。
- `-f`：指定文件名。**多账号必须分开命名**，不要都用默认 `id_ed25519`。
- 口令（passphrase）建议设置，可配合 `ssh-agent` 免重复输入。

```bash
# 把公钥内容复制到剪贴板（Windows 用 clip，WSL 用 clip.exe 或直接 cat）
cat ~/.ssh/id_ed25519_kian03k.pub
```

然后把 `.pub` 内容粘到 GitHub → Settings → SSH and GPG keys → New SSH key。

### 1.4.2 多账号隔离：`~/.ssh/config`

一把公钥只能绑定一个 GitHub 账号（GitHub 侧硬性限制，重复添加会报 `Key is already in use`），所以多账号必须「一账号一密钥 + Host 别名」。

```sshconfig
# 个人账号
Host github.com-personal
    HostName github.com
    User git
    IdentityFile ~/.ssh/id_ed25519_kian03k
    IdentitiesOnly yes

# 工作账号
Host github.com-work
    HostName github.com
    User git
    IdentityFile ~/.ssh/id_ed25519_work
    IdentitiesOnly yes
```

Git 仓库里用别名代替真实域名：

```bash
git remote set-url origin git@github.com-personal:kian03k/kian-notes.git
```

`IdentitiesOnly yes` 不要省——否则 ssh 会把 agent 里所有密钥挨个试一遍，触发 `Too many authentication failures`。

### 1.4.3 验证

```bash
ssh -T git@github.com-personal
# 期望输出：Hi kian03k! You've successfully authenticated, but GitHub does not provide shell access.
```

报 `Permission denied (publickey)` 时按顺序查：公钥是否已上传 → `IdentityFile` 路径是否正确 → `ssh -vT` 看实际用了哪把密钥。

> 22 端口被封锁时，GitHub 支持 SSH over 443：`HostName ssh.github.com` + `Port 443`。是否可用取决于所在网络。

## 1.5 忽略文件：首推之前就要写好

`.gitignore` 只对**未跟踪**文件生效，推上去之后再补是无效的（正确补救见 [[gitignore常见问题]]）。所以规则是：**`git add` 之前先写 `.gitignore`**。

最小可用模板：

```gitignore
node_modules/
__pycache__/
*.pyc
.env
.venv/
dist/
*.log
.DS_Store
*Zone.Identifier      # Windows 下载文件带的 NTFS 附加流
```
