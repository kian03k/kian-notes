# git 标签

标签是**指向某个提交的固定指针**。分支会随新提交前移，标签不会——所以「标记某个时间点的版本」只能用标签，不能用分支。

## 一、轻量标签与附注标签

| | 轻量（lightweight） | 附注（annotated） |
| --- | --- | --- |
| 创建 | `git tag v1.0` | `git tag -a v1.0 -m "说明"` |
| 本质 | 一个指向提交的引用 | 独立对象，含作者、日期、说明、可签名 |
| `git show` 输出 | 只有提交信息 | 标签自身的元信息 + 提交信息 |
| 适用 | 临时锚点、本地快照 | 正式发布 |

正式发布一律用附注标签：它记录了「谁在什么时候因为什么打的」，轻量标签没有这层信息。

## 二、创建

```bash
# 在当前提交上
git tag -a v1.2.0 -m "1.2.0：导出功能上线"

# 补打历史提交
git log --oneline -20                      # 先找 SHA
git tag -a v1.1.0 9f3c2a1 -m "1.1.0"

# 按时间范围找「某天最后那次提交」
git log --since="2026-10-01" --until="2026-10-02" --oneline

# 签名标签（有 GPG 密钥时）
git tag -s v1.2.0 -m "1.2.0"
```

命名约定：

- 发布版本用语义化 `v1.2.3`（major.minor.patch）。
- 时间点快照用 `v2026-10-01`。
- 两类不要混用，否则 `git tag -l` 的输出难以排序和判断。

## 三、推送

**标签不会随 `git push` 自动上传**，这是最常见的「本地有、远端没有」问题。

```bash
git push origin v1.2.0        # 单个
git push origin --tags        # 全部（含轻量）
git push origin --follow-tags # 只推附注标签，推荐
```

## 四、查看

```bash
git tag                       # 全部
git tag -l "v1.*"             # 按模式过滤
git show v1.2.0               # 标签详情 + 指向的提交
git tag -n5                   # 列出标签并带上说明前 5 行
git describe --tags           # 当前提交相对最近标签的位置，如 v1.2.0-3-g9f3c2a1
```

## 五、回到某个标签

```bash
git switch --detach v2026-10-01     # 只读查看，进入 detached HEAD
git switch -                        # 一键切回原来的分支
```

`git switch -` / `git checkout -` 表示「上一个 HEAD 位置」，相当于 `cd -`。忘了原来在哪个分支时：

```bash
git reflog
# 输出中 HEAD@{0} 那行的 "moving from <分支> to <标签>" 就写着你从哪来
```

要在标签版本上继续改，必须开分支。detached HEAD 状态下直接提交会生成游离提交，不挂任何分支，`git switch` 一走就容易找不到：

```bash
git switch -c hotfix/from-1.2.0 v1.2.0
```

## 六、删除与改名

```bash
git tag -d v1.2.0                  # 本地删除
git push origin --delete v1.2.0    # 远端删除
```

标签没有改名命令，只能「删掉旧的 + 在新位置重打 + 重推」。如果别人已经拉过旧标签，他们的本地标签不会自动更新，需要他们自己 `git tag -d v1.2.0 && git fetch --tags`。

## 七、标签 vs 分支

| | 标签 | 分支 |
| --- | --- | --- |
| 会移动吗 | 不会 | 会随提交前移 |
| 语义 | 「这是 v1.2.0 这个版本」 | 「我在这里继续开发」 |
| 适合 | 发布、里程碑、可复现快照 | 日常开发 |
| 数量 | 少而明确 | 用完即删 |

「我需要回到某天的代码跑一遍」——用标签。用分支保存历史快照，最后会得到一堆不知道能不能删的僵尸分支。
