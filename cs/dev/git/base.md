VS Code 是 Git 开发的高效工具，既支持**图形化操作**（无需记命令，适合新手），也兼容**命令行操作**（灵活高效）。我会按「日常开发流程」整理最常用的 Git 操作，结合你当前的 WSL + GitHub 环境，确保每一步都实用。

### 前提
1. 已在 VS Code 中打开克隆好的 GitHub 仓库（WSL 环境）；
2. 左下角已显示 WSL 环境，终端为 Ubuntu 环境。

---

## 一、图形化操作（VS Code 内置 Git 界面，新手首选）
VS Code 的 Git 图形化功能集中在**左侧边栏的源代码管理面板**（图标是「分支+文件」样式，快捷键 `Ctrl + Shift + G`）。

### 1. 基础配置（首次使用）
无需额外操作，只要 WSL 终端已执行 `git config --global` 配置（用户名/邮箱），VS Code 会自动读取。

### 2. 暂存修改（把代码变更加入 Git 跟踪）
- 场景：修改/新增/删除文件后，准备提交
- 操作：
  1. 打开源代码管理面板（`Ctrl + Shift + G`）；
  2. 看到修改的文件列表（红色/绿色标识变更）：
     - 单文件暂存：点击文件右侧的 `+` 图标；
     - 全部暂存：点击顶部的 `+` 图标（或面板右上角「暂存所有更改」）；
  3. 暂存后文件会从「更改」区移到「暂存的更改」区（变绿色）。

### 3. 提交修改（把暂存的变更保存到本地 Git）
- 场景：暂存后，记录本次修改的备注
- 操作：
  1. 在源代码管理面板的「消息输入框」中输入提交备注（必填，如「修复XX bug/新增XX功能」）；
  2. 点击输入框右侧的 ✔️ 图标（提交）；
  3. 提交成功后，「暂存的更改」区会清空，本地 Git 记录更新。

### 4. 推送代码到 GitHub（本地提交 → 远程仓库）
- 场景：本地提交后，同步到 GitHub
- 操作：
  1. 提交完成后，源代码管理面板顶部会显示「↑X」（X 是待推送的提交数）；
  2. 点击「↑」图标（推送），或右键空白处 → 选择「推送」；
  3. 首次推送可能提示选择分支（选 `main` 即可），等待几秒即可同步到 GitHub。

### 5. 拉取远程最新代码（GitHub → 本地）
- 场景：团队协作/本地与远程代码不一致时，先拉取最新版本
- 操作：
  1. 源代码管理面板右上角 → 点击「↓」图标（拉取）；
  2. 或右键空白处 → 选择「拉取」；
  3. 等待终端显示「拉取成功」，本地代码会同步远程最新版本。

### 6. 克隆远程仓库（从 GitHub 下载代码到本地）
- 场景：首次获取仓库代码
- 操作：
  1. VS Code 顶部菜单 → `文件 → 克隆存储库`；
  2. 输入 GitHub 仓库地址（SSH 格式：`git@github.com:kian03k/kian-notes.git`）；
  3. 选择本地保存路径（WSL 路径，如 `/home/kian/my_project`）；
  4. 等待克隆完成，点击「打开仓库」即可编辑。

### 7. 撤销操作（新手必备）
- 撤销未暂存的修改：右键文件 → 「放弃更改」（恢复到上一次提交的状态）；
- 撤销已暂存的修改：右键暂存的文件 → 「取消暂存更改」（回到未暂存状态）；
- 撤销已提交的修改：不建议直接图形化操作，建议用命令行（见下文）。

### 8. 查看提交历史
- 操作：
  1. 源代码管理面板右上角 → 点击「...」（更多操作）→ 「查看提交历史」；
  2. 会打开「时间线」面板，显示所有提交记录（包括作者、时间、备注、修改的文件）。

## 二、命令行操作（WSL 终端，高效灵活）
VS Code 的终端（`Ctrl + ``）默认是 WSL 环境，以下是日常最常用的 Git 命令，与图形化操作一一对应：

### 1. 基础配置（首次使用）
```bash
# 配置用户名（已配过可跳过）
git config --global user.name "kian03k"
# 配置邮箱（已配过可跳过）
git config --global user.email "你的GitHub邮箱"
```

### 2. 克隆远程仓库
```bash
# 克隆你的 GitHub 仓库（SSH 地址）
git clone git@github.com:kian03k/kian-notes.git
# 进入仓库目录
cd kian-notes
```

### 3. 暂存修改
```bash
# 暂存单个文件（替换为你的文件名）
git add README.md
# 暂存所有修改（最常用）
git add .
```

### 4. 提交修改
```bash
# 提交并添加备注（备注必填，用双引号包裹）
git commit -m "新增VS Code Git操作说明"
# 若暂存+提交一步到位（适合小修改）
git commit -am "修复代码格式问题"
```

### 5. 推送代码到 GitHub
```bash
# 推送到远程 main 分支（默认分支）
git push origin main
# 首次推送（若提示分支关联问题）
git push -u origin main
```

### 6. 拉取远程最新代码
```bash
# 拉取远程 main 分支的最新代码
git pull origin main
# 简化版（已关联分支时）
git pull
```

### 7. 查看状态（最常用，检查文件变更）
```bash
# 查看当前文件的修改状态（哪些未暂存/已暂存）
git status
```

### 8. 查看提交历史
```bash
# 简洁版（显示提交ID、作者、时间、备注）
git log --oneline
# 详细版（显示所有提交细节）
git log
```

### 9. 撤销操作
```bash
# 撤销未暂存的修改（恢复单个文件）
git checkout -- README.md
# 撤销所有未暂存的修改
git checkout .
# 撤销已暂存的修改（回到未暂存状态）
git reset HEAD README.md
# 撤销最近一次提交（保留代码修改，回到暂存前）
git reset --soft HEAD^
```

### 10. 分支操作（进阶，多版本开发用）
```bash
# 查看所有分支（本地+远程）
git branch -a
# 创建新分支
git checkout -b feature/new-function
# 切换到 main 分支
git checkout main
# 合并分支（把 feature 分支合并到 main）
git merge feature/new-function
# 推送新分支到远程
git push origin feature/new-function
```

## 三、图形化 vs 命令行 对比（怎么选？）
| 操作类型       | 图形化操作                | 命令行操作                |
|----------------|---------------------------|---------------------------|
| 优势           | 直观、无需记命令、新手友好 | 灵活、高效、支持复杂操作  |
| 劣势           | 复杂操作（如分支合并）不便 | 需记忆命令、新手易输错    |
| 适用场景       | 日常提交/推送/拉取/暂存   | 分支管理/撤销/高级配置    |

---

### 总结
1. **新手优先图形化**：暂存、提交、推送、拉取用 VS Code 源代码管理面板（`Ctrl + Shift + G`），无需记命令；
2. **高效用命令行**：`git add .`、`git commit -m`、`git push/pull` 是日常高频命令，记熟后比图形化更快；
3. **核心流程**：修改代码 → 暂存（图形/`git add`）→ 提交（图形/`git commit`）→ 推送（图形/`git push`），拉取（图形/`git pull`）放在修改前更稳妥。

按这个流程操作，就能覆盖 90% 的日常 Git 开发场景，适配你当前的 WSL + GitHub 环境。
