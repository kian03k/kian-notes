## 二、这 5 张图是怎么来的

**不是笔记生成的，是当年 `mat.py` 跑出来的产物。** 一一对应关系：

| 图 | 生成函数（`mat.py`） | 画的是 |
| --- | --- | --- |
| `total_loss.png` | `get_total_loss()` | `total_loss` 随 epoch 变化 |
| `iou_loss.png` | `get_iou_loss()` | `iou_loss` 随 epoch 变化 |
| `conf_loss.png` | `get_conf_loss()` | `conf_loss` 随 epoch 变化 |
| `cls_loss.png` | `get_cls_loss()` | `cls_loss` 随 epoch 变化 |
| `totel.png` | `get_totel()` | 上面四个拼成 2×2，标题「训练结果展示」 |

每张图的 **x 轴是 epoch（1~311）**，y 轴是对应 loss。注意 `.png` 里的中文标题靠 `SimHei` 字体渲染，**在无该字体的机器上会变方块**。

从 `train_log.txt` 里读出来的事实：

| 模型 | YOLOX-S（`yolox_voc_test_s`，**Params 8.94 M**） |

### ✅ 画 loss 曲线 —— 2026-10-15 实测通过

#### 跑之前先看环境

这台机器上科学计算库的分布（实测）：

| 环境 | python | numpy | pandas | matplotlib | 备注 |
| --- | --- | --- | --- | --- | --- |
| WSL `conda web-dev` | 3.12.13 | ✅ 2.4.4 | ✅ 3.0.2 | ❌ | **画图只差 matplotlib** |
| WSL `conda data-py314` | 3.14.4 | ❌ | ❌ | ❌ | 名字像数据环境，其实几乎是空的 |
| WSL `conda base` | 3.13.12 | ❌ | ❌ | ❌ | 纯净 |
| Windows 侧 Python | 3.13.12 | ❌ | ❌ | ❌ | 装了也连不上源（代理拦） |
| WSL 系统字体 | — | — | — | — | **原本一个中文字体都没有** |

> 💡 所以要跑，只要补 **matplotlib**；中文标题还要补**字体**（否则全是方块）。

#### 准备工作（一次性）

**① 补 matplotlib**（别直接装进 conda env，用独立环境更干净）

```bash
# 基于 web-dev 建一个独立环境，继承它的 numpy/pandas，只单独装 matplotlib
~/miniconda3/envs/web-dev/bin/python -m venv --system-site-packages ~/tmp/plotenv
~/tmp/plotenv/bin/pip install -i https://mirrors.aliyun.com/pypi/simple/ matplotlib
```

**② 补中文字体**（不用 sudo，直接借 Windows 的）

```bash
mkdir -p ~/.local/share/fonts
cp /mnt/c/Windows/Fonts/simhei.ttf /mnt/c/Windows/Fonts/msyh.ttc ~/.local/share/fonts/
fc-cache -f ~/.local/share/fonts
```

#### 跑法 ①：原版 `mat.py`

```bash
cd _训练日志样例
python mat.py          # ⚠️ 这样跑只会 print 一行空，什么都画不出来
```

> ⚠️ 原脚本 `if __name__ == "__main__":` 里 **5 个函数调用全被注释掉了**（第 118–122 行）。
> 要手动取消注释才有输出：

```python
if __name__ == "__main__":
    get_total_loss()
    get_iou_loss()
    get_conf_loss()
    get_cls_loss()
    get_totel()
```

**实测结果**（2026-10-15，WSL / matplotlib 3.11.2）——解开注释后 5 张图全部正常产出：

| 重跑产物 | 大小 | 归档原件 |
| --- | --- | --- |
| `total_loss.png` | 34,817 B | 33,294 B |
| `iou_loss.png` | 42,446 B | 36,809 B |
| `conf_loss.png` | 55,443 B | 33,468 B |
| `cls_loss.png` | 56,288 B | 26,838 B |
| `totel.png` | 150,154 B | 138,846 B |

> 大小略有差异正常（matplotlib 版本 / dpi 不同），**曲线本身是一致的**。

还踩到 3 个小坑：

1. **`SyntaxWarning: invalid escape sequence '\-'`** —— 第 12 行 `re.split('[,\-]', i)` 不是 raw 字符串，`\-` 在 Python 3.12+ 会告警。改成 `r'[,\-]'` 即可。
2. **它会往当前目录写 5 张 png**，和归档原件**同名会直接覆盖** —— 想保留原件就换个目录跑（我就是这么做的）。
3. **中文标题靠 `SimHei`**，字体没装就是方块。

#### 跑法 ②：笔记里的重写版（推荐）

见 [[08-训练日志分析与可视化]] §8.2。逻辑更干净：按 `epoch` 聚合、不写死 `iter` 号。

**实测结果**：

```
matplotlib 3.11.2 | SimHei: True
共 311 个 epoch（1 ~ 311）
  total_loss    10.8 → 4.6
  iou_loss       4.3 → 2.3
  conf_loss      5.6 → 1.8
  cls_loss       0.8 → 0.6
出图: A_loss_curves.png 173,962 bytes
```

> 注意两版**取值点不同**，数值自然对不上：原版取每个 epoch 第 40 个 iter，重写版取每个 epoch **最后一条**（第 70 个 iter）。
> 例：epoch 1 原版是 `13.0`，重写版是 `10.8` —— 都对，只是"epoch 内哪个点"的区别。
