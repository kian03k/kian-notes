# 08 · 训练日志分析与可视化

> 模型跑完不等于结束。**日志是训练的"体检报告"** —— loss 降没降、有没有过拟合、哪一项在恶化，全在里面。
> 这一篇讲一件事：**把训练日志/CSV 解析出来 → 画成 loss 曲线**。
> 素材：`_训练日志样例/`（一份真实的 YOLOX-S 训练日志 + 原解析脚本 + 5 张曲线图）。
> 那个目录里每张图是什么、怎么跑，见 [[素材说明]]。

## 8.1 两种常见的训练输出格式

不同框架吐出来的东西不一样，但套路是通的：

| 格式 | 代表 | 形态 | 怎么读 |
| --- | --- | --- | --- |
| **文本日志** | YOLOX、MMDetection、PaddleDetection | 每行一条 iter 记录 | 正则解析 → numpy → 画图 |
| **CSV** | **Ultralytics YOLOv8/v5** | 一行一个 epoch | `pandas.read_csv` 直接读 |

### 格式一：YOLOX 文本日志

`train_log.txt` 里真实的一行长这样（2720 行；这次跑到第 **311/500** 个 epoch 时崩了，`total_loss` 从 10.8 降到 4.6）：

```
2023-05-27 01:45:10.709 | INFO | yolox.core.trainer:after_iter:253 - epoch: 1/500, iter: 40/72,
mem: 3957Mb, iter_time: 0.945s, data_time: 0.697s, total_loss: 13.0, iou_loss: 4.5, l1_loss: 0.0,
conf_loss: 7.6, cls_loss: 0.9, lr: 7.716e-04, size: 544, ETA: 11:57:50
```

要点：
- **每行一个 iter 打点**，`after_iter` 是 loguru 的打点位置（用它过滤最稳）
- 关心的字段：`epoch`、`iter`、`total_loss`、`iou_loss`、`conf_loss`、`cls_loss`、`lr`
- **每个 epoch 打印 7 次**：`iter: 10/72`、`20/72` … `70/72`（共 72 个 iter，每 10 个报一次）
- 日志**尾部还跟着一段异常栈**（这次跑崩了）—— 用 `after_iter` 过滤能天然绕开

### 格式二：YOLOv8 `results.csv`

毕设那次 `yolov8n-cls` 果蔬分类（10 epoch）的输出：

```csv
                  epoch,             train/loss,  metrics/accuracy_top1, ..., val/loss, lr/pg0, ...
                      1,                 3.3546,                0.53561, ...,   3.3716, ...
```

要点：
- ⚠️ **列名带前导空格**（Ultralytics 的老毛病），直接 `df["train/loss"]` 会报 KeyError
- 同时有 `train/loss` 和 `val/loss` → 可以判断过拟合

## 8.2 demo ①：解析 YOLOX 日志画 loss 曲线

原脚本（`mat.py`）在这份日志上**是能跑通的**（它筛 `iter: 40/72`，正好每个 epoch 命中一条，共 311 条），但有两个毛病：**把迭代号写死成 `40/72`**（数据集体量一变就失效 —— 这份日志尾部就混进了 `/83` 的记录），以及踩了列表引用的坑（见 8.5）。下面是重写版。

```python
import re
import matplotlib.pyplot as plt

plt.rcParams["font.sans-serif"] = ["SimHei"]     # 中文
plt.rcParams["axes.unicode_minus"] = False

LOG = "train_log.txt"                            # 归档在 _训练日志样例/
KEYS = ["total_loss", "iou_loss", "conf_loss", "cls_loss"]

# (?<![A-Za-z_]) —— 保证匹配的是"独立字段名"
# 否则 "after_iter:253" 里的 iter 也会被抓进来
FIELD = re.compile(r"(?<![A-Za-z_])(epoch|iter|total_loss|iou_loss|conf_loss|cls_loss):\s*([0-9./]+)")


def parse(path):
    """每个 epoch 取最后一条记录 → {epoch: {loss名: 值}}"""
    by_epoch = {}
    for line in open(path, encoding="utf-8"):
        if "after_iter" not in line:             # 只认训练打点行
            continue
        kv = dict(FIELD.findall(line))
        if "total_loss" not in kv:
            continue
        ep = int(kv["epoch"].split("/")[0])      # "1/500" → 1
        by_epoch[ep] = {k: float(v) for k, v in kv.items() if k in KEYS}
    return by_epoch


data = parse(LOG)
epochs = sorted(data)
print(f"共 {len(epochs)} 个 epoch（{epochs[0]} ~ {epochs[-1]}）")
for k in KEYS:
    print(f"  {k:11s} {data[epochs[0]].get(k):6} → {data[epochs[-1]].get(k)}")
```

出图（2×2 汇总）：

```python
fig, axes = plt.subplots(2, 2, figsize=(12, 8))
fig.suptitle("YOLOX 训练 loss 曲线", fontsize=16)

for ax, key in zip(axes.ravel(), KEYS):
    ys = [data[e].get(key) for e in epochs]
    ax.plot(epochs, ys)
    ax.set_title(key)
    ax.set_xlabel("epoch")
    ax.set_ylabel(key)
    ax.grid(alpha=0.3)

plt.tight_layout()
plt.savefig("loss_curves.png", dpi=120)          # 无界面环境用 savefig
plt.show()
```

> 为什么"按 epoch 取最后一条"而不是像原脚本那样筛 `iter: 40/72`？
> 原写法是"每个 epoch 固定取第 40 个 iter"。在**这份**日志上没问题（72 个 iter 是固定的），但迭代总数取决于训练集大小 ÷ batch_size —— 这份日志尾部就已经出现了 `iter: x/83` 的记录（各 6 条），说明中途换过配置。一旦 `/72` 变了，原脚本筛出来就是空的。**按 `epoch` 分组取最后一条更通用。**

> ✅ 以上代码 2026-10-15 在 WSL 的 `data-py314` 环境（Python 3.14.4 + matplotlib 3.11.2）实测跑通，出图 176 KB。依赖与字体怎么配，见 [[素材说明]] §四。
> 顺带一提：两版**取值点不同**（原版取第 40 个 iter，本版取该 epoch 最后一条），所以数值对不上——epoch 1 原版是 `13.0`、本版是 `10.8`。都对，只是取的"epoch 内哪个点"不一样。

## 8.3 demo ②：读 YOLOv8 的 `results.csv`

CSV 就省事多了，`pandas` 两行搞定：

```python
import pandas as pd
import matplotlib.pyplot as plt

df = pd.read_csv("results.csv")
df.columns = df.columns.str.strip()              # ⚠️ 去掉列名的前后空格

# loss 对比：train 下降、val 是否跟着
df.plot(x="epoch", y=["train/loss", "val/loss"], marker="o", title="loss")
plt.show()

# 分类任务的准确率
df.plot(x="epoch", y=["metrics/accuracy_top1", "metrics/accuracy_top5"],
        marker="o", title="accuracy")
plt.show()
```

> 检测任务（`yolo detect`）的 CSV 列名不一样，是 `box_loss / cls_loss / dfl_loss / mAP50 / mAP50-95` —— 同理替换 y 轴即可。

## 8.4 曲线怎么看（判读口诀）

| 现象 | 含义 |
| --- | --- |
| train ↓，val 跟着 ↓，最后都趋平 | ✅ 正常收敛 |
| train 一直 ↓，**val 中途开始 ↑** | ⚠️ **过拟合** → 加数据增强 / 早停 / 正则 |
| 两条都几乎不降 | lr 太小、模型容量不够、或数据/标签有问题 |
| loss 突然 NaN / 暴涨 | lr 太大，或数据里有脏样本 |
| `cls_loss` 高 | 分类学不好（类别难分 / 类别不平衡） |
| `iou_loss` / `l1_loss` 高 | 框不准（回归没学好） |
| `conf_loss` 高 | 置信度学不好（正负样本失衡） |

> 一句话：**先看形状对不对，再看数值漂不漂亮**。

## 8.5 ⚠️ 踩坑

1. **列表引用共享**（原 `mat.py` 里作者自己留了注释）：
   ```python
   used = []
   temp = []
   for ...:
       temp.append(x)
       used.append(temp)     # ← 存的是同一个列表的引用！
       temp.clear()          # ← 这行会把 used[-1] 也清空
   ```
   ✅ 正确做法：`temp = []` 重新绑定一个新对象，或 `used.append(list(temp))` 存副本。
2. **字段名被 substring 误匹配**：过滤/正则时 `iter` 会命中 `after_iter:253`、`iter_time` →
   正则前面加 `(?<![A-Za-z_])` 断言。
3. **`results.csv` 列名带空格** → `.str.strip()`。
4. **中文字体**：`plt.rcParams["font.sans-serif"] = ["SimHei"]`，否则标题变方块。（Linux/WSL 上要先有中文字体，见 [[素材说明]]）
5. **非 raw 字符串里的 `\-`**：原 `mat.py` 写的是 `re.split('[,\-]', i)`，Python 3.12+ 会报 `SyntaxWarning: invalid escape sequence '\-'`。正则一律加 `r` 前缀：`re.split(r'[,\-]', i)`。

## 8.6 小结
