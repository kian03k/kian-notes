你的想法完全正确，这正是 Docker Compose 的魅力所在！

简单来说：
*   **切换版本**：是的，直接修改 `docker-compose.yml` 文件即可。
*   **删除旧镜像**：**不会自动删除**。旧的镜像文件会保留在你的电脑上，需要手动清理。

下面我为你详细解释一下整个过程和原理。

### 🚀 如何平滑切换 MySQL 版本

假设你想从 `mysql:8.0.33` 切换到 `mysql:8.0.36`。

1.  **修改配置文件**
    打开你的 `docker-compose.yml` 文件，找到 `image` 这一行：
    ```yaml
    services:
      mysql:
        image: mysql:8.0.36  # 只需修改这里的版本号
        container_name: mysql-prod
        # ... 其他配置保持不变
    ```

2.  **拉取新镜像并重启服务**
    在终端执行以下命令，Docker Compose 会自动完成剩下的工作：
    ```bash
    # 1. 先拉取新版本镜像到本地
    docker compose pull

    # 2. 强制重新创建容器，Docker 会使用新拉取的镜像
    docker compose up -d --force-recreate
    ```

**这个过程发生了什么？**
Docker Compose 会识别到配置发生了变化，然后执行一个“优雅”的替换流程：
1.  停止正在运行的旧 MySQL 容器 (`mysql-prod`)。
2.  删除这个旧的容器实例。
3.  使用你新指定的 `mysql:8.0.36` 镜像，结合你原有的配置（端口、环境变量、**尤其是数据挂载**），创建一个全新的容器并启动。

**为什么数据不会丢失？**
还记得我们之前强调的“挂载”吗？你的数据存储在 WSL2 的 `./data` 目录中，而容器只是一个“读写工具”。无论容器被删除和重建多少次，只要 `volumes` 配置不变，新容器启动后依然会挂载到同一个 `./data` 目录，你的所有数据都会完好无损。

### 🧹 如何处理旧的镜像文件

当你完成版本切换后，旧的 `mysql:8.0.33` 镜像仍然会静静地躺在你的 `/var/lib/docker` 目录里，占用磁盘空间。Docker 不会自动删除它，因为可能还有其他项目在使用这个旧版本。

如果你想清理掉它，可以手动执行以下命令：

```bash
# 查看当前电脑上所有的 MySQL 镜像
docker images mysql

# 删除指定的旧版本镜像 (例如 8.0.33)
docker rmi mysql:8.0.33
```

**一个小提示**：如果你不确定是否还有其他地方在用旧镜像，或者想一次性清理所有未被容器使用的“悬空”镜像，可以使用更安全的命令：
```bash
# 清理所有未被任何容器使用的镜像
docker image prune
```

### ✨ 总结

| 你的操作 | 结果 | 注意事项 |
| :--- | :--- | :--- |
| 修改 `docker-compose.yml` 中的版本号 | 配置文件已更新 | 这是第一步 |
| 执行 `docker compose up -d --force-recreate` | 旧容器被替换为新版本的容器 | 数据因挂载而安全 |
| (可选) 执行 `docker rmi <旧版本>` | 释放旧镜像占用的磁盘空间 | Docker 不会自动完成此操作 |

所以，你的理解非常到位。通过修改配置文件来管理环境，正是 Docker Compose “声明式”和“可版本控制”的核心优势。
