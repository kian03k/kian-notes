###  MySQL 8.0 容器化部署标准化指南 (WSL2/Docker)

**版本**：1.0
**适用环境**：WSL2 (Ubuntu 20.04/22.04) + Docker Engine
**部署方式**：Docker Compose

---

###  核心解惑：Docker、MySQL 与文件的关系

在开始敲命令之前，我们先解决你最困惑的问题：**“Docker 是如何找到 MySQL 配置文件的？”**

为了理解这个关系，我们可以打一个比方：

- **Docker 镜像 (Image)**：就像是一个**“精装样板房”**。它是只读的，里面已经预装了 MySQL 软件，并且有默认的装修风格（默认配置）。
- **Docker 容器 (Container)**：是你根据样板房**“实际住进去的家”**。它是活的、可运行的。
- **宿主机目录 (WSL2 文件夹)**：就像是**“仓库”或“外部硬盘”**。
- **挂载 (Volume Mount)**：这是最关键的动作！相当于**“打通墙壁”**。

**Docker 是如何找到配置的？**
我们在 `docker-compose.yml` 中写了一行映射规则（例如 `./conf/my.cnf` 映射到 `/etc/mysql/conf.d/my.cnf`）。
这就好比告诉 Docker：“**启动的时候，不要只看样板房里的默认设置，请去我的‘仓库’（WSL2 的 `./conf` 目录）里拿那个叫 `my.cnf` 的文件，直接覆盖到容器里的 `/etc/mysql/conf.d/` 目录下。**”

> **结论**：Docker 并不是“寻找”配置文件，而是我们**强制把宿主机的文件塞给了容器**。容器启动时，会优先读取被“塞进来”的文件，从而覆盖默认设置。

###  目录结构规划

我们需要在 WSL2 中建立一个“仓库”，用来存放数据和配置。

**操作步骤**：
在 WSL2 终端中执行：

```bash
# 1. 创建项目根目录
mkdir -p ~/docker-env/mysql/{data,conf,log}

# 2. 进入目录
cd ~/docker-env/mysql
```

**目录说明**：
- `data/`：**仓库的数据区**。MySQL 产生的所有表、数据都存在这里。
- `conf/`：**仓库的配置区**。存放我们自定义的 `my.cnf`。
- `log/`：**仓库的日志区**。存放运行记录。

###  编写配置文件

我们需要两个核心文件。

#### 3.1 创建数据库配置文件 (my.cnf)
这个文件是我们要“塞”给 MySQL 的自定义设置。

```bash
vim conf/my.cnf
```

填入以下内容：

```ini
[mysqld]
# 基础配置：字符集与时区
character-set-server=utf8mb4
collation-server=utf8mb4_unicode_ci
default-time-zone='+08:00'

# 网络配置：允许所有 IP 连接（在容器内部监听）
bind-address=0.0.0.0

# 性能与日志
max_connections=500
slow_query_log=1
slow_query_log_file=/var/log/mysql/slow.log
long_query_time=2

# 安全配置：防止加载本地文件攻击
local_infile=0
```

#### 3.2 创建 Docker Compose 编排文件 (docker-compose.yml)
这是**总指挥**，告诉 Docker 怎么启动、去哪里找文件。

```bash
vim docker-compose.yml
```

填入以下内容（请仔细阅读注释）：

```yaml
# version: '3.8' 新版本无需配置版本
services:
  mysql:
    image: mysql:8.0.33          # 1. 指定具体镜像版本（去仓库取货）
    container_name: mysql-prod   # 2. 给容器起个固定的名字
    restart: always              # 3. 重启策略：挂了自动重启
    
    environment:
      MYSQL_ROOT_PASSWORD: "MyStrongPassword123!" # 4. 设置 Root 密码
      MYSQL_DATABASE: "app_db"                    # 5. 初始化时自动创建一个业务库
      TZ: Asia/Shanghai                           # 6. 设置时区
    
    ports:
      - "3306:3306"              # 7. 端口映射：宿主机端口:容器端口
    
    volumes:
      # 8. 【核心】数据挂载：把宿主机的 ./data 目录，映射到容器内的 /var/lib/mysql
      # 效果：容器里写数据，实际是写到了 WSL2 的 ./data 文件夹里
      - ./data:/var/lib/mysql
      
      # 9. 【核心】配置挂载：把宿主机的 ./conf/my.cnf，映射到容器内的 /etc/mysql/conf.d/my.cnf
      # 效果：MySQL 启动时，会读取这个被映射进来的文件，从而应用我们的自定义配置
      - ./conf/my.cnf:/etc/mysql/conf.d/my.cnf
      
      # 10. 日志挂载
      - ./log:/var/log/mysql
    
    command: 
      - --lower_case_table_names=1 # 11. 忽略表名大小写（兼容 Windows 开发习惯）
```

###  启动与验证

**启动服务**：
```bash
docker compose up -d
```
*解释：Docker 会读取 `docker-compose.yml`，下载镜像，创建容器，并执行我们在 `volumes` 里定义的“挂载”操作。*

**查看日志**：
```bash
docker compose logs -f mysql
```
如果看到 `ready for connections`，说明启动成功。

---

###  深度验证：配置是否生效？

我们可以通过进入容器来验证“挂载”是否成功。

**1. 进入容器内部**
```bash
docker exec -it mysql-prod bash
```

**2. 检查配置文件是否被“塞”进来了**
在容器内执行：
```bash
cat /etc/mysql/conf.d/my.cnf
```
*现象：你会看到和你刚才在 WSL2 里编辑的一模一样的内容。这就证明了 Docker 成功把宿主机的文件映射进来了。*

**3. 登录 MySQL 验证参数**
```bash
mysql -u root -p
# 输入密码：MyStrongPassword123!
```

在 MySQL 命令行中执行：
```sql
-- 查看字符集配置（应显示 utf8mb4）
SHOW VARIABLES LIKE 'character_set_server';

-- 查看最大连接数（应显示 500）
SHOW VARIABLES LIKE 'max_connections';
```

### ️ 常用运维指令速查

- **停止服务**：`docker compose down`
- **重启服务**：`docker compose restart`
- **查看状态**：`docker compose ps`
- **进入数据库**：`docker exec -it mysql-prod mysql -u root -p`
- **查看实时日志**：`docker compose logs -f`

###  举一反三：如何安装其他组件？

安装 Redis、Nginx 或 MongoDB 的逻辑完全一致，只需三步：

1. **建目录**：在 WSL2 里创建对应的 `data` 和 `conf` 目录。
2. **写配置**：
    - 编写对应的配置文件（如 `redis.conf`）。
    - 修改 `docker-compose.yml`，把 `image` 改成 `redis`，把 `volumes` 路径改成 Redis 的路径。
3. **起服务**：运行 `docker compose up -d`。
