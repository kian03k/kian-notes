# 数通岗位面试总览与答题策略

> 面试怎么准备、不同岗位问什么、怎么答才不像背书、怎么反问。**具体每天做什么见 [[备考计划]]**；题库入口见 [[OSPF-题库]]、[[BGP-题库]]、[[VXLAN-EVPN-题库]]、[[智算网络与RoCE-题库]]、[[交换与高可用-题库]]、[[综合场景与排障题库]]。

## 一、面试的四个环节，每个考什么

| 环节 | 考什么 | 准备重点 |
|---|---|---|
| **自我介绍**（1–2 分钟） | 表达能力、履历匹配度 | 提前写好，练到不看稿 |
| **项目深挖** | 是不是真做过、有没有 owner 意识 | 每个项目准备 3 个"坑"的故事 |
| **技术问答** | 知识体系完整性 | 题库刷到 L2 能讲两分钟 |
| **反问/收尾** | 主动性、判断力 | 准备 2–3 个有质量的问题 |

**时间分配建议**：技术问答占 50%，项目准备占 30%，自我介绍和反问各 10%。

## 二、不同岗位，侧重完全不同

| 岗位类型 | 高频考点 | 少问的 |
|---|---|---|
| **运营商 / 集成商交付** | 割接流程、BRAS/PPPoE、故障处理、跨方协调 | EVPN 五种路由、SPF 算法 |
| **数据中心 / 云网络** | VXLAN/EVPN、M-LAG、Spine-Leaf、BGP 选路 | 运营商业务、SDH |
| **智算网络** | RoCE/PFC/ECN、五平面、轨优化、慢节点定位 | STP、VRRP 细节 |
| **厂商原厂（华为/新华三）** | 协议底层、排障深度、认证知识 | 商业流程 |
| **甲方运维** | 稳定性、变更管理、监控体系、成本 | 方案设计 |

**策略**：投不同岗位，把对应那一列准备到"能讲十分钟"，其他列保证"能讲一分钟"。

## 三、答题的三种框架

### 框架 1：现象 → 定位 → 根因 → 解决（排障类）

任何排障题都用这个。**关键是要说"我用什么判据排除的"**，不是"我敲了什么命令"。

> "现象是 X。我先看 Y 排除了 A 方向，再对比 Z 发现是 B 问题，根因是 C，解决方式是 D。"

### 框架 2：分层 → 对比 → 收窄（设计/排查类）

> "分三层看：协议层……工程层……运维层……"

这个框架的杀伤力在于**显示你有体系，不是零散知识**。

### 框架 3：约束 → 动作 → 结果（经历类）

> "当时的约束是 X（工期紧/多方依赖/不能中断），我做了 Y，结果是 Z（按期/一次通过/零事故）。"

**交付岗尤其要用这个框架** —— 因为交付岗的价值不在技术难度，在**在约束下拿到结果**。

## 四、怎么答才不像背书

### 对比：背书 vs 有理解

**背书版**：
> "OSPF 有五种报文：Hello、DD、LSR、LSU、LSAck。邻居状态有七个：Down、Init、2-Way……"

**有理解版**：
> "OSPF 五种报文其实分两组：Hello 负责发现和保活，另外四个是 LSDB 同步用的——DD 交换摘要、LSR 要详情、LSU 送详情、LSAck 确认。为什么要 LSAck？因为 IP 不可靠，OSPF 自己在上面做了可靠泛洪。"

**区别**：前者是列表，后者是**因果关系**。面试官听到"为什么"，就知道你真懂了。

### 三个提升"有理解"感的技巧

1. **先说结论，再说理由**（别绕）
2. **主动说缺陷**："这个方案的问题是……"（显示你评估过，不是只会背优点）
3. **落到具体数字/场景**："默认 180 秒，意味着最坏情况三分钟才发现对端挂了"

### 千万不要说的话

| 别说 | 为什么 | 改成 |
|---|---|---|
| "这个我没做过，不太清楚" | 直接放弃 | "这块我没直接做过，但按我的理解是……如果不对请您指正" |
| "书上说……" | 显得没实操 | "我实际遇到的情况是……" |
| "应该是……吧" | 不确定还硬猜 | "我确认一下：是 A 还是 B？" |
| "这个很简单" | 显得轻浮 | "这块我比较熟，我讲一下我的做法" |
| "我不会，但我可以学" | 空话 | 说具体："这块我目前是 X 水平，Y 方向我在补" |

## 五、被问倒了怎么办（必须准备）

**三步**：

1. **承认边界**（不装懂）："这个细节我不确定"
2. **给出推理**（显示思维）："但从原理推断应该是……因为……"
3. **转向熟悉区**（不失分）："我实际处理过的是相关的 X 场景，当时是这么做的……"

**核心**：面试官不怕你不知道，怕你**不知道还硬编**。硬编被拆穿，比承认不会扣分多得多。

## 六、项目怎么讲（交付岗专用）

### 每个项目准备三层内容

| 层次 | 内容 | 讲多久 |
|---|---|---|
| **电梯版**（30 秒） | 什么项目、多大规模、你负责什么、结果如何 | 开场用 |
| **标准版**（2 分钟） | 加上技术方案、关键难点 | 常规展开 |
| **深挖版**（10 分钟） | 加上踩的坑、判断依据、如果重做会怎么改 | 被追问时 |

### 一定要准备的三个故事

1. **最难的一次排障**：现象 → 怎么定位 → 根因 → 学到什么
2. **最紧的一次工期**：约束是什么 → 怎么安排 → 结果
3. **最主动的一次改进**：发现了什么问题 → 做了什么 → 带来什么变化

**这三个故事覆盖了 90% 的行为面试题**（"你遇到最大的困难""你怎么处理压力""你做过什么超出职责的事"）。

### 讲项目的禁忌

- ❌ 只讲技术，不讲**你的判断**（面试官想知道你怎么想的）
- ❌ 只用"我们"，不说"我"（分不清你的贡献）
- ❌ 夸大（一追问就穿帮，比说小更糟）
- ❌ 讲成流水账（没有重点）

## 七、反问环节（很关键，很多人浪费了）

**好的反问**（显示你在评估岗位，也在思考）：

1. "这个岗位目前团队多少人？主要负责哪类项目？"
2. "网络这块现在的自动化程度怎么样？是手工配还是有平台？"
3. "团队现在最头疼的问题是什么？"
4. "这个岗位未来一年最重要的目标是什么？"

**坏的反问**：

- ❌ "加班多吗"（可以问，但要换个说法："项目交付期的节奏一般是怎么样的"）
- ❌ "我能学到东西吗"（学生气）
- ❌ 什么都不问（显得没兴趣）

**一个高段位反问**：

> "如果我入职，前三个月您希望我先把什么做好？"

这个问题让面试官开始**想象你在岗位上**，心理上已经把你当同事了。

## 八、技术面的"三层深度"自检法

对每个技术点，问自己三个问题：

1. **是什么**（能不能一句话说清）
2. **为什么这么设计**（能不能说出取舍）
3. **实际怎么用/怎么出问题**（有没有具体场景）

**只到第一层 = 背书；到第二层 = 懂原理；到第三层 = 有经验。**

面试前自检：把技能栏里每个词过一遍，**至少要到第二层，核心的到第三层**。到不了的词，技能栏上就该降级或删掉。

## 九、临场心态

- **不会就不会**：技术面本来就是筛边界，问到你不会的地方是正常的
- **答错不崩**：一道题答错不影响整体，崩了才影响
- **主动引导**：把问题往你熟的领域带（"这块我了解，我实际做过的是……"）
- **节奏**：每题先说结论，再展开；别一开口讲五分钟
- **诚实**：没做过就说没做过，但说清你的理解——这个行业里"诚实 + 有逻辑"比"什么都会"更值钱

## 附：一句话记住每个协议

| 协议 | 一句话 |
|---|---|
| OSPF | 大家拿同一张地图，自己算最短路 |
| BGP | 不看快慢看策略，稳比快重要 |
| VXLAN | 二层帧装进三层包，突破 4094 的限制 |
| EVPN | 用 BGP 告诉大家"MAC 在哪"，不用泛洪 |
| M-LAG | 两台设备装成一台用，但各自活着 |
| RoCE | 网卡直接读内存，绕开 CPU |
| PFC | 快满了就喊上游停一下，一跳一跳传 |
| ECN | 快满了先打个标记，让发送端自己慢下来 |

**这八句话能顺口说出来，技术面的开场就稳了。**
