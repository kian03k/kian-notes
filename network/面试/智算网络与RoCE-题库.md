# 智算网络与 RoCE 题库

> 40 道题。原理细节见 [[RoCE与无损网络]]。

**这个方向的面试特点**：几乎没有"标准答案"，面试官在判断你**是不是真在集群里干过**。所以答题的关键是**说具体的事**——多少卡、哪个参数、什么现象、怎么定位。

---

## L1 基础必答（13 题）

### 1. 智算网络和普通数据中心网络最大的区别是什么？

**三个根本区别**：

1. **流量模型**：普通 DC 是南北向（客户端→服务器）、收敛比可接受；智算是**全互联、同步突发**（AllReduce），几千 GPU 同时拉数据，Incast 极严重
2. **丢包容忍度**：普通 DC 丢包重传几十 ms 没感觉；智算丢一个包，整轮迭代等待，性能直接掉
3. **组网目标**：普通 DC 追求带宽利用率和多租户隔离；智算追求**尾时延（P99）和确定性**

所以智算网络的核心指标不是平均带宽，是 **P99 时延**。

### 2. 什么是 RoCE？RoCEv1 和 v2 的区别？

RoCE = RDMA over Converged Ethernet，把 InfiniBand 的 RDMA 语义搬到以太网上。**网卡直接读写对端内存，绕过 CPU 和内核协议栈**，微秒级。

- **RoCEv1**：二层，自定义 EtherType（0x8915），不可路由，已淘汰
- **RoCEv2**：**IP + UDP 4791**，可路由，当前标准

### 3. RDMA 为什么快？

三个原因：① **零拷贝**：数据直接从应用内存到网卡，不经过内核缓冲区 ② **内核旁路**：用户态直接操作网卡队列，不陷内核 ③ **无 CPU 中断**：网卡完成操作后直接写内存（轮询模式）

**对比 TCP**：TCP 要经过内核协议栈、有拷贝、有中断、有上下文切换，单次操作几十微秒；RDMA 可以到 1–2 微秒。

### 4. 为什么智算网络必须无损？

AllReduce 是**同步操作**，一个节点慢全体等待（木桶效应）。而 TCP 的丢包重传是毫秒级（RTO 最小 200ms，快速重传也要几十 ms），训练一轮迭代可能只有几百毫秒——一次丢包就让这轮翻倍。

所以：**丢一个包 = 整个集群卡一下**，这是"无损"的意义。

### 5. PFC 是什么？

**Priority Flow Control**（802.1Qbb），基于**优先级**的逐跳反压。

交换机某个队列快满了 → 向上游发 Pause 帧，指定"暂停第 X 优先级"→ 上游停止发该优先级的包 → 水位降到 XON 阈值恢复。

**两个关键点**：① **逐跳**（hop-by-hop），只压上游一跳 ② **按优先级**，只暂停无损队列，其他队列不受影响。

### 6. ECN 是什么？

**Explicit Congestion Notification**，交换机在拥塞**早期**给报文打 CE 标记，接收端回 **CNP** 通知发送端降速（DCQCN）。

**作用**：把拥塞消解在 PFC 触发之前，避免反压扩散。

### 7. PFC 和 ECN 分别解决什么问题？为什么两个都要？

- **ECN 是主力**：主动降速，让发送端在队列满之前慢下来
- **PFC 是兜底**：ECN 来不及（突发流量）时保证零丢包

**只用 PFC**：反压会逐跳扩散，一个慢节点拖垮全网
**只用 ECN**：突发时来不及标记，会丢包

**一句话答案**：ECN 让拥塞不发生，PFC 让拥塞不丢包。缺一不可。

### 8. 什么是 DCQCN？

运行在**网卡侧**的拥塞控制算法，配合 ECN 工作：收到 CNP → 降速（乘性减）→ 逐步恢复（加性增）。

**关键**：RoCE 的拥塞控制是**网卡 + 交换机双侧**的事。交换机配好 ECN，网卡 DCQCN 参数不对，照样跑不好。

### 9. 智算集群的"五平面"是哪五个？

参数面、样本面、业务面、带内管理、带外管理。

| 平面 | 承载 |
|---|---|
| 参数面 | GPU 梯度同步（AllReduce） |
| 样本面 | 训练数据读取（存储→计算） |
| 业务面 | 平台调度、用户访问 |
| 带内管理 | SSH、SNMP、批量部署（走业务网，逻辑隔离） |
| 带外管理 | BMC/IPMI、交换机管理口（物理独立） |

### 10. 带内管理和带外管理的区别？

- **带外**：物理独立的网，走 BMC/IPMI。**服务器关机、系统崩了照样通**（BMC 有独立电源和小系统）。远程开关机、刷固件、KVM、PXE 重装
- **带内**：走业务网 IP，依赖 OS 正常。SSH、SNMP、Ansible

**一句话**：带外是救命通道，带内是日常运维。

### 11. 为什么要分五个平面？不能合并吗？

四条理由：① **流量模型不同**（参数面同步突发、样本面持续大流量、业务面普通），混跑互相踩 ② **故障域隔离**（参数面调 PFC 出问题不能拖垮业务） ③ **带宽独立规划**（参数面无收敛、业务面可收敛） ④ **安全边界**（带外绝不能暴露到业务网）。

### 12. 参数面用什么组网？

**两层 Spine-Leaf，无收敛（1:1）**，Leaf 全连 Spine，三层 eBGP + ECMP。

**为什么不上 VXLAN**：没有大二层需求、封装开销和 MTU 都是负担、多一层故障点。

### 13. 什么是收敛比？智算为什么要 1:1？

收敛比 = 下行带宽 / 上行带宽。1:1 表示无收敛，每台服务器的带宽需求都能被上行满足。

智算必须 1:1 因为：所有 GPU 同步通信，如果收敛比 >1，上行链路会拥塞 → PFC 反压 → 训练变慢。**普通 DC 可以用 3:1 甚至更高，智算不行。**

## L2 进阶（15 题）

### 14. PFC 死锁是怎么产生的？

A 压 B、B 压 C、C 又压 A，形成环，全网卡死。

**成因**：① 拓扑/路由有环 ② PFC 反压跨了无损/非无损边界 ③ buffer 分配不当导致异常反压链。

**缓解**：PFC 死锁检测、PFC Watchdog（超时直接 shutdown 端口）。

### 15. 什么是 PFC 风暴？怎么防？

**一个慢节点**（网卡故障、GPU 卡住、驱动问题）持续不接收 → 反压一级级传回 → **整个集群都慢**。

**防**：**PFC Watchdog** —— 检测某端口持续反压超过阈值（如 200ms）→ 判定异常 → shutdown 该端口，牺牲一个节点保全网。

**排查**：逐台查 PFC 反压计数，找反压源。

### 16. 什么是 Headroom？为什么重要？

PFC 是逐跳的，从"下游发现快满"到"上游真的停下来"之间，上游还在发包，这段**在途数据必须有地方放**，否则丢包。预留的这块 buffer 就是 headroom。

**计算**（简化）：`Headroom = 链路速率 × 反压响应时间 × 传播延迟`

**关键**：400G 链路的 headroom 需求是 100G 的 4 倍；线缆越长需求越大。**Headroom 不够 = 配了 PFC 还是丢包**。

### 17. ECN 阈值设太低会怎样？设太高呢？

- **太低**：稍微有点流量就标记 → 发送端过度降速 → **带宽跑不满，训练变慢**（最难受的故障：没人报警，只是慢）
- **太高**：来不及标记就撞到 PFC → 反压 → 尾时延抖动

**典型配置**：低阈值 20–30% 队列，高阈值 40–50%。

### 18. 什么是 Incast？智算里为什么严重？

**Incast**：多个发送方同时向一个接收方发数据，接收端瞬间被淹没。

智算里 AllReduce 的 Reduce 阶段就是典型 Incast——几千个 GPU 同时把梯度发给一个节点。

**缓解**：ECN 早期标记、DCQCN 快速降速、减少收敛比、调整 AllReduce 算法（Ring / Tree）。

### 19. 什么是轨优化（Rail-Optimized）组网？

**问题**：一台服务器 8 张 GPU、8 个 400G 口。随便接 Leaf 会导致 GPU0→GPU0 和 GPU0→GPU7 的跳数不同，时延不均。

**做法**：**同号 GPU 固定接到同一个"轨"（Rail）**。

```
服务器1: GPU0→Leaf0, GPU1→Leaf1, ..., GPU7→Leaf7
服务器2: GPU0→Leaf0, GPU1→Leaf1, ..., GPU7→Leaf7
```

这样 **GPU0 → 对端 GPU0 永远两跳**，任意两台服务器同号卡之间路径完全一致。

**为什么重要**：AllReduce 主要是同号卡之间通信，轨优化让时延最均匀。

### 20. 什么是超节点（Super POD）？

把柜内/柜间的高速互联做成统一的大二层或专用互联，**1024 卡甚至更多卡在一个逻辑节点内**。

**价值**：减少跨节点跳数，提升 AllReduce 效率。需要**高密交换机 + 铜缆/光缆背板**配合。

### 21. 400G 组网有什么特殊要求？

① **散热**：400G 光模块功耗高，机柜风道要规划 ② **光纤**：多模/单模选择、极性要正确（错纤很常见） ③ **headroom**：400G 的 headroom 需求是 100G 的 4 倍 ④ **FEC**：400G 通常需要 RS-FEC，会增加时延（几百 ns） ⑤ **布线密度**：一台服务器 8 个口，布线量巨大，要提前规划。

### 22. 训练突然变慢，但没丢包，怎么查？

**排查顺序**：

1. 看 **PFC 反压计数**（`display interface | include pause`）——增长说明有反压
2. 看 **ECN 标记计数**——标记太多说明阈值太低
3. 看 **各链路利用率**——是否某条打满（ECMP 不均）
4. 看 **光模块**（光功率、温度、CRC 计数）——误码会导致重传
5. 看 **网卡侧**（DCQCN 参数、重传计数）
6. 看 **GPU 侧**（温度降频、显存、NCCL 日志）

**核心心法**："慢"和"断"是两种故障，慢的排查要从**计数器和利用率**入手，不是从 ping 入手。

### 23. 怎么定位"慢节点"？

参数面流量是"多对一 + 一对多"。某台服务器接收有问题，它的**所有入向流量都会触发 PFC 反压**。

1. 在**所有 Leaf 上行口**查 PFC 反压计数
2. 反压计数增长快的端口 → 反压源在这后面
3. 逐级向下定位到具体服务器
4. 查该服务器的网卡状态（`ibstat` / `ethtool -S`）、GPU 温度、驱动日志

### 24. RoCE 和 InfiniBand 怎么选？

| | RoCEv2 | IB |
|---|---|---|
| 性能 | 略逊（多一层封装、FEC 时延） | **最好**（原生无损、无 FEC） |
| 成本 | 低（以太网生态） | 高（专用设备、线缆） |
| 生态 | 开放，多厂商 | 封闭（NVIDIA） |
| 运维 | 复用现有网络技能 | 需要专门技能 |
| 现状 | 主流（尤其国产化要求） | 高端训练集群仍有市场 |

**答法**：中小规模、要国产化、要复用现有网络团队 → RoCE；超大规模极致性能 → IB。现在 RoCE 是主流方向。

### 25. 智算网络怎么和计算、存储协同？

**网络是前置依赖**：网络不通，计算和存储无法联调。所以交付节奏是**网络先通**，为 AI 服务器部署和性能测试留出窗口。

**接口协同**：存储侧要知道网络的 VLAN/VNI/网关；计算侧要知道参数面的地址规划、网卡绑定方式（bond/lacp/双活）；平台侧要知道带外管理地址。

**这是交付岗最核心的软技能**：不是技术难度，是**多方接口对齐**。

### 26. DSCP 和 802.1p 在智算网络里怎么用？

智算网络是**三层组网**，所以用 **DSCP** 做端到端标记（DSCP 可以跨三层传递，802.1p 出三层就丢）。

典型规划：RoCE 流量标 **DSCP 46/48（EF/CS6）** 或厂商模板值 → 交换机 `trust dscp` → 映射到无损队列 → 该队列开 PFC + ECN。

**坑**：交换机默认 **untrust**，不配 `trust dscp` 的话所有流量都进默认队列，**PFC/ECN 全都不生效**。

### 27. 为什么业务流量不能进无损队列？

PFC 是**队列级**的。业务突发把无损队列打满 → 触发 PFC → 反压 RoCE 流量 → **业务流量拖慢训练**。

这就是五平面分开的深层原因之一：**队列隔离**。

### 28. 智算交付的典型流程？

1. **方案设计**：五平面规划、地址规划、DSCP 规划、QoS/无损参数
2. **等中标 / 到货**：设备到货、光模块、线缆
3. **布线**：光纤铺设、标签、极性核对
4. **配置制作**：基线配置、批量生成
5. **设备调试**：单机配置、链路打通
6. **联调**：参数面 / 样本面 / 业务面分别验证
7. **性能测试**：NCCL / AllReduce 带宽测试、PFC/ECN 调优
8. **验收**：端口级检查、测试报告

**面试点**：这个流程里有大量"不归你管"的依赖（中标、到货、布线、计算/存储进度），交付岗的价值就是**在这些约束下按期交付**。

## L3 深挖（8 题）

### 29. PFC 和 ECN 的阈值怎么配合？

**原则**：ECN 必须在 PFC 之前生效。

- **ECN 低阈值 < ECN 高阈值 < PFC XOFF 阈值**
- 队列水位上涨时：先触发 ECN 标记（发送端降速）→ 如果还涨 → 触发 PFC

如果 ECN 阈值高于 PFC 阈值，ECN 永远不生效，全靠 PFC 反压 → 反压扩散。

### 30. 为什么 PFC 需要 `trust dscp`？

PFC 是**按优先级**暂停的。交换机必须知道每个报文属于哪个优先级——这个信息来自报文自带的 DSCP/802.1p。

如果交换机不信任报文标记（默认 untrust），所有报文都映射到默认优先级 → PFC 不知道该暂停谁 → 要么全停（影响业务），要么不停（丢包）。

### 31. RoCE 的 MTU 要不要调大？

**建议调大**（Jumbo Frame，通常 9000 或至少 4200）。

原因：① 减少报文数量 → 减少 PFC/ECN 的处理开销 ② 减少中断和 CPU 开销 ③ 大包传输效率高。

**但要注意**：全路径 MTU 必须一致（包括服务器网卡、交换机、存储），否则会分片或丢包。改 MTU 是**全链路**的事，不能只改一端。

### 32. 智算网络的故障为什么比普通 DC 更难查？

① **慢故障比断故障多**：网络是"通"的，只是慢，没有告警，只能靠计数器和性能数据 ② **多因素耦合**：网卡、驱动、GPU、交换机、光模块、布线都可能 ③ **规模大**：几百上千台设备，逐个查不现实 ④ **影响范围大**：一个慢节点拖垮全网，但根因在一个点上。

**所以智算运维的核心能力是"从全局数据定位单点"**，不是敲命令。

### 33. 交付 1024 卡超节点，网络侧最大的挑战是什么？

**参考答案框架**（要有具体感）：

> 规模带来的三个挑战：① **布线量**：一台服务器 8 个 400G 口，1024 卡就是 128 台服务器、1024 根光纤，极性和标签任何一根错都要花时间定位 ② **参数一致性**：几百台交换机的 PFC/ECN/DSCP 参数必须完全一致，靠手工配不可能，必须工具化批量下发 ③ **故障定位**：任何一个慢节点都会影响全局，需要从 PFC 反压计数逐级定位。

**加分点**：说出"参数一致性靠工具而不是手工"——这是交付岗往工程化走的标志。

### 34. 什么是 NCCL？和网络有什么关系？

NCCL 是 NVIDIA 的集合通信库，实现 AllReduce / AllGather / AlltoAll 等操作。

**和网络的关系**：NCCL 会自动选择通信算法（Ring / Tree / NVLink）和网络路径。网络的拓扑（轨优化）、PFC/ECN 参数、MTU 都会影响 NCCL 的实测带宽。

**测试方法**：`all_reduce_perf` 测 AllReduce 带宽，对比理论值（比如 400G × 8 = 3.2T，实测应该在 80% 以上）。

**面试点**：能说出"用 NCCL 测试验证网络调优效果"，说明你真的做过性能验证，不只是配完就交。

### 35. 无损网络里，为什么不能只靠"加大 buffer"？

① buffer 再大也会满，只是推迟问题 ② 大 buffer 增加时延（排队时间变长）——智算对时延敏感 ③ 反压一旦发生，buffer 大小只决定"什么时候开始反压"，不解决"反压扩散" ④ 成本：大 buffer 的芯片贵。

**所以**：buffer + ECN（主动降速）+ PFC（兜底）三者配合才是正确解法。

### 36. 如果客户的现网交换机不支持 PFC/ECN，怎么办？

① 升级设备（智算必须支持） ② 降级方案：用 TCP 替代 RDMA（性能损失大，但能跑） ③ 用 IB 组网 ④ 分段：核心用支持无损的设备，接入用普通设备（但反压边界要小心）。

**答法**：这不是技术选择，是**成本和性能的取舍**，要跟客户讲清代价。

## L4 场景题（4 题）

### 37. 交付现场，网络通了但训练性能只有理论值的 50%，怎么查？

**分层排查**：

1. **先确认瓶颈在不在网络**：单机内测试（NVLink）、单服务器到单服务器测试（点对点带宽）、全集群测试（AllReduce）——逐级排除
2. **网络层**：链路利用率是否均匀（ECMP 哈希）、有没有 PFC 反压、ECN 标记率、CRC 错误
3. **参数层**：DSCP 映射、PFC/ECN 阈值、MTU
4. **网卡层**：DCQCN 参数、bond 模式、中断绑定
5. **拓扑层**：是否按轨优化接线、收敛比、跨 Spine 跳数

**关键**：50% 这种"腰斩"通常是**单链路瓶颈**或**收敛比问题**，不是随机丢包。

### 38. 割接窗口只有 4 小时，怎么保证按时完成？

① **提前准备**：配置预生成（工具批量生成）、脚本预演 ② **模块化**：按平面/机柜分批，每批可独立验证 ③ **并行**：多个小组同时作业，但要提前划分好边界 ④ **验证清单**：每步有明确的验证命令和判据 ⑤ **回滚预案**：配置备份 + 快速回退脚本 ⑥ **关键路径优先**：先保证参数面通，业务面可以后续优化。

### 39. 客户临时加需求（增加一个 VNI / 改一个网段），怎么快速响应？

**如果做了工具化**：改配置模板参数 → 一键生成全套配置 → 批量下发 → 验证。这是"工具化"的真正价值——**不是省人力，是缩短响应时间**。

**如果没做**：手工改，风险高、易漏。这就是为什么交付岗要做工具。

### 40. 你怎么理解"智算网络交付"这个岗位？

**不要答成"配交换机"**。

> 智算网络交付是在**多方依赖、紧工期、高一致性要求**下，把一张复杂的网络按标准交付出去。技术上是五平面组网、RoCE 无损调优；工程上是参数一致性、批量配置、验收标准；协作上要和计算、存储、平台、现场对齐接口。核心价值不是技术难度，是**确定性**——在约束下按时、一次通过。

**"确定性"这个词很关键**，它把交付岗和研发岗区分开了。

## 速记卡

- RoCEv2 = UDP 4791；RoCEv1 已淘汰
- 无损双保险：**ECN 主力（主动降速）+ PFC 兜底（零丢包）**
- 阈值关系：ECN 低 < ECN 高 < PFC XOFF
- PFC 三问题：死锁、风暴、headroom 不足
- 五平面：参数 / 样本 / 业务 / 带内 / 带外
- 参数面：两层 Spine-Leaf、1:1 无收敛、eBGP+ECMP、**不上 VXLAN**
- 轨优化：同号 GPU 接同一 Rail，保证同号卡之间两跳
- 慢节点定位：查 PFC 反压计数，逐级向下
- `trust dscp` 不配 = PFC/ECN 全部失效
- 业务流量不能进无损队列
