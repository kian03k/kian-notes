# 交换与高可用题库

> 30 道题：Eth-Trunk、M-LAG、堆叠、VRRP、STP、QoS。原理细节见 [[M-LAG与高可用组网]]、[[QoS与优先级映射]]。

**这个方向的面试规律**：M-LAG 是数据中心岗的必问项，问法很固定——"你们服务器怎么双归的""M-LAG 和堆叠什么区别""peer-link 断了怎么办"。STP 在老网络岗位问得多，数据中心岗反而少。

---

## L1 基础必答（10 题）

### 1. 服务器双归有哪三种做法？

| 方案 | 特点 |
|---|---|
| **堆叠** | 两台合成一台逻辑设备，控制面统一 |
| **VRRP** | 两台独立，网关虚拟化，**主备**，备机闲置 |
| **M-LAG** | 两台独立，**控制面独立、数据面双活** |

**为什么现在主流是 M-LAG**：双活跑满带宽、单台可独立升级、故障域隔离。

### 2. Eth-Trunk 的两种模式？

- **手工模式**：不协商，物理 Up 就参与转发，只能靠物理状态检测故障
- **LACP 模式（static）**：通过 LACPDU 协商，能发现"物理 Up 但逻辑不通"，**生产推荐**

### 3. Eth-Trunk 成员口必须一致的参数？

速率、双工、VLAN 配置、MTU、端口类型（access/trunk）、QoS 配置。

**不一致后果**：加入不了，或者加入后 `Unselect` 不转发。

### 4. Eth-Trunk 怎么负载分担？有哪些模式？

按哈希：`src-dst-mac`、`src-dst-ip`、`src-dst-ip + l4-port`（五元组）。

**坑**：同一对 IP 之间的流量永远走同一条成员链路（哈希固定），大流量场景会不均。

### 5. M-LAG 的核心概念有哪些？

- **DFS Group**：M-LAG 管理单元
- **peer-link**：两台设备之间的直连链路
- **M-LAG 接口**：面向服务器/下联的跨设备 Eth-Trunk
- **Primary / Secondary**：主备角色，**只影响控制面，数据面双活**
- **MAD**：双主检测

### 6. M-LAG 的"主备"是什么意思？

**控制面主备，数据面双活**。主设备负责处理协议报文、同步表项；两台都在转发流量。

**这是它比 VRRP 强的核心**——VRRP 备机纯粹闲置。

### 7. peer-link 和 M-LAG 接口有什么区别？

| | peer-link | M-LAG 接口 |
|---|---|---|
| 连到哪 | 两台 M-LAG 设备之间 | 下联服务器 |
| 作用 | 传协议报文、同步表项、**跨设备转发** | 承载业务流量 |
| 带宽要求 | **高**（跨设备流量都走它） | 按业务需求 |

### 8. 什么是脑裂（双主）？怎么检测？

**peer-link 断了**，两台都认为对方挂了 → 都变 Primary → MAC/ARP 表不一致 → 流量混乱。

**检测**：BFD（推荐，毫秒级）、管理网 ping、Eth-Trunk 成员口检测（不推荐）。

**检测到后的动作**：通常让 Secondary 的 M-LAG 接口 **Error-Down**，保证只有一台转发。

### 9. STP 有几种端口状态？

`Blocking → Listening → Learning → Forwarding`（802.1D），RSTP 简化为 `Discarding → Learning → Forwarding`。

**RSTP 的四种端口角色**：根端口（Root）、指定端口（Designated）、替代端口（Alternate，替代根口）、备份端口（Backup，替代指定口）。

### 10. VRRP 的虚拟 MAC 是什么？抢占吗？

虚拟 MAC：`00-00-5E-00-01-{VRID}`。

**默认抢占**（和 OSPF DR 相反）——优先级高的设备恢复后会抢回 Master。

## L2 进阶（13 题）

### 11. M-LAG 和堆叠的本质区别？

| | 堆叠 | M-LAG |
|---|---|---|
| 控制面 | **统一**（一台主设备管全部） | **独立**（各自管理） |
| 升级 | 整堆重启（业务中断） | **单台独立升级** |
| 故障域 | 控制面故障影响两台 | 隔离 |
| 跨设备带宽 | 堆叠链路（易成瓶颈） | peer-link |
| 配置 | 简单（一套配置） | 复杂（两台分别配，要一致） |

**答法**：堆叠是"变成一台"，M-LAG 是"两台协作"。前者简单但耦合，后者复杂但健壮。

### 12. M-LAG 建立不起来，怎么查？

① 两台 **DFS Group 编号**是否一致 ② **M-LAG 接口编号是否一致**（最常见的错误） ③ peer-link 是否 Up ④ 成员口配置是否一致（VLAN/速率/MTU） ⑤ `display dfs-group 1` 看角色和状态。

### 13. M-LAG 场景下，跨设备流量走哪里？

**走 peer-link**。

典型场景：服务器从 Leaf1 进来，但目的地/上行只在 Leaf2 侧 → 流量必须过 peer-link。

**所以 peer-link 带宽要按"最坏情况全走一台"规划**。

### 14. M-LAG 需要 STP 吗？

**M-LAG 接口本身不需要**（逻辑上是一个 Eth-Trunk，无环）。但：
- **peer-link 上要配 STP 保护**（防止和外部交换机形成环）
- 外部还有二层环路时，STP 仍然要工作

**别以为上了 M-LAG 就能关 STP。**

### 15. 什么是 M-LAG 的优雅升级（graceful）？

升级一台设备时，先把它从转发路径中优雅摘除（流量切到另一台），升级完再切回来，业务不中断。

**前提**：另一台有足够带宽承接全部流量。

### 16. STP 的根桥怎么选？怎么优化？

选 **优先级最低 + MAC 最小**。默认优先级 32768。

**优化**：① 手工指定根桥（`stp root primary`）② 核心设备优先级设为 0 或 4096 ③ 接入层配 `stp edged-port`（接终端的口直接进转发，跳过 30s 收敛） ④ 配 `bpdu-protection`（edge 口收到 BPDU 就 shutdown，防止环路）。

### 17. RSTP 比 STP 快在哪？

① 端口状态从 5 个简化到 3 个 ② **P/A 机制**（Proposal/Agreement）：指定端口主动发起协商，不必等 30s 计时 ③ 边缘端口（edged-port）直接转发 ④ 拓扑变化只通知到根桥，不泛洪全网。

### 18. 什么是 BPDU 保护、根保护、环路保护？

| 保护 | 作用 |
|---|---|
| **BPDU 保护** | 边缘端口收到 BPDU → shutdown 端口（防私接交换机） |
| **根保护** | 指定端口收到更优 BPDU → 进入 discarding（防止接入层抢根桥） |
| **环路保护** | 根端口/替代端口长时间收不到 BPDU → 进入 discarding（防止单向链路形成环） |

### 19. QoS 里 802.1p 和 DSCP 的区别？

- **802.1p**：二层 VLAN Tag 里的 PCP，**3 bit（0–7）**，出三层就丢
- **DSCP**：IP 头 ToS 高 6 bit，**6 bit（0–63）**，可跨三层

**结论**：三层组网用 DSCP，纯二层用 802.1p。

### 20. 什么是 trust 模式？不配会怎样？

交换机决定"信不信报文自带的优先级"。

- `trust dscp` / `trust 802.1p` / 默认 **untrust**

**不配 `trust dscp` 的后果**：所有流量映射到默认优先级（通常 0）→ QoS 策略、PFC 全部失效。**这是智算网络"配了 PFC 还丢包"的第一排查项。**

### 21. PQ 和 WRR 的区别？

- **PQ（严格优先级）**：高优先级队列有包就一直发，发完才轮到下一级。**时延最低，但低优先级可能饿死**
- **WRR（加权轮询）**：按权重轮流发，保证各队列带宽比例

**实战**：控制协议和语音用 PQ，业务用 WRR/DRR。

### 22. 监管（Policing）和整形（Shaping）的区别？

**监管是丢，整形是等。**

- **监管**（CAR）：超速率直接丢弃或降级，用于**入口**
- **整形**：超速率缓存起来慢慢发，用于**出口**，代价是增加时延

### 23. 什么是 WRED？和 ECN 什么关系？

**WRED**：队列水位到阈值时**按优先级随机丢包**，避免 TCP 全局同步。

**ECN 是 WRED 的"不丢包版本"**——把"丢"换成"打 CE 标记"。所以配 ECN 阈值本质上就是配 WRED 阈值。

## L3 深挖（5 题）

### 24. 为什么数据中心不用 VRRP 而用 M-LAG？

① **VRRP 备机闲置**，浪费一半带宽 ② 切换秒级，业务有感知 ③ 上行需要 STP 防环，链路利用率低 ④ M-LAG 双活、毫秒级收敛、可独立升级。

**但 VRRP 仍有场景**：跨厂商环境（M-LAG 是厂商私有的）、简单组网、成本敏感。

### 25. M-LAG 有哪些厂商私有性？

M-LAG 是**各厂商私有实现**，名字不同：
- 华为：M-LAG
- 思科：vPC
- H3C：IRF（更接近堆叠）
- 锐捷：VSU

**跨厂商不能互通** —— 这是 M-LAG 最大的局限。所以混合组网时只能用 VRRP/STP 或者标准 LACP。

### 26. peer-link 带宽不够会有什么现象？

跨设备流量拥塞 → 时延增大、丢包。

**现象**：服务器访问"另一侧"的服务时慢，本地侧正常。

**排查**：`display interface Eth-Trunk0` 看 peer-link 利用率。

**优化**：① 加大 peer-link 带宽 ② 调整上行链路让流量本地转发（比如上行也做 M-LAG，让流量就近出去）。

### 27. 一个 VLAN 里两台交换机都跑 STP，又配了 M-LAG，会冲突吗？

不会冲突，但要注意：
- M-LAG 接口在逻辑上是一条链路，STP 只看到一个口
- peer-link 要配 STP 保护（`stp disable` 或 `edged-port`），否则两台 M-LAG 设备之间可能形成 STP 环

**关键**：M-LAG 和 STP 是**互补**的，不是替代——M-LAG 解决双归接入，STP 解决剩余的二层环路。

### 28. 大规模二层网络怎么避免广播风暴？

① **控制广播域大小**（VLAN 划分）② **广播风暴抑制**（`broadcast-suppression`）③ **STP 保护**（BPDU/根/环路保护）④ **M-LAG 替代 STP**（减少环路）⑤ **VXLAN 替代大二层**（从根本上消除广播域）。

## L4 场景题（2 题）

### 29. 割接时怎么保证 M-LAG 不断？

① 先确认 peer-link 和另一台设备状态正常 ② 分批操作（先备后主） ③ 用 `m-lag graceful` 优雅升级 ④ 割接前 `display dfs-group 1` 确认主备角色 ⑤ 准备好回滚。

### 30. "服务器网络时通时断"，怎么查？

**如果是 M-LAG 环境，先怀疑双主**：

1. `display dfs-group 1` 看两台是不是都 Primary
2. 检查 peer-link 和 MAD 配置
3. 两台都在应答 ARP → 服务器 ARP 表来回变 → 时通时断

**其他原因**：① 链路聚合成员口配置不一致 ② 光模块劣化（CRC 增长）③ STP 拓扑震荡 ④ MAC 漂移（环路）。

## 速记卡

- 双归三方案：堆叠（合一）、VRRP（主备）、M-LAG（双活）
- M-LAG 主备 = **控制面主备，数据面双活**
- peer-link：传协议 + 同步表项 + **跨设备转发**，带宽要够
- M-LAG 接口编号两台必须一致
- 脑裂检测：BFD 优先，检测到让 Secondary Error-Down
- 监管是丢（入口），整形是等（出口）
- QoS 不配 `trust dscp` = 全部失效
- M-LAG 是厂商私有（华为 M-LAG / 思科 vPC）
