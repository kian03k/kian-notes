# 华为数通设备命令与特性速查

> 交付现场天天用的命令、设备系列定位、常见特性开关。按"排查场景"组织，不是按手册目录。

## 一、设备系列定位

### CloudEngine（数据中心）

| 系列 | 定位 | 典型场景 |
|---|---|---|
| **CE12800 / 16800** | 大型框式核心 | 大型 DC 核心、Spine |
| **CE9860 / 9865** | 高密 400G 盒式 | 智算 Spine / Leaf |
| **CE8850 / 8851** | 100G/400G 盒式 | DC Leaf、中小型 Spine |
| **CE6881 / 6865** | 25G/100G 接入 | 服务器接入 Leaf |
| **CE5881** | 25G 接入 | 中小 DC |

智算场景常见组合：**Spine = CE9865/8850，Leaf = CE8850/6881**。

### S 系列（园区/企业）

| 系列 | 定位 |
|---|---|
| **S12700 / S7700** | 框式核心/汇聚（CSS 堆叠） |
| **S6730 / S5732** | 万兆汇聚 |
| **S5735 / S5720** | 千兆接入 |

### 关键差异（面试可能问）

- **CE 系列**：原生支持 VXLAN/EVPN、M-LAG、RoCE 无损、大缓存，数据中心专用
- **S 系列**：园区为主，支持 iStack/CSS 堆叠、VRRP，VXLAN 支持视型号（部分仅支持 VXLAN 二层）

## 二、基础信息与健康检查

```
display version                  # 版本、运行时间、补丁
display device                   # 单板/电源/风扇状态
display power                    # 电源状态
display fan                      # 风扇状态
display temperature              # 温度（过热会降频/告警）
display alarm active             # 当前告警（现场第一件事）
display cpu-usage                # CPU 利用率
display memory-usage             # 内存利用率
display clock                    # 时间（日志排查基础）
display current-configuration    # 当前配置
display saved-configuration      # 已保存配置（对比有没有存盘）
```

**现场套路**：新接手一台设备，先 `display alarm active` + `display device` + `display version`，三分钟摸清底细。

## 三、接口与链路

```
display interface brief                       # 所有接口 up/down + 速率 + 利用率
display interface 400GE1/0/1                  # 单接口详情
display interface 400GE1/0/1 | include error  # 错误计数
display interface transceiver verbose         # 光模块信息（光功率、温度、厂商）
display interface description                 # 接口描述（谁连谁，靠这个）
display eth-trunk                             # 所有 Eth-Trunk 概览
display eth-trunk 10                          # 成员口状态（Status: Selected/Unselect）
display lacp peer                             # LACP 对端
```

**错误计数怎么读**（重要）：

| 计数 | 含义 | 常见原因 |
|---|---|---|
| `CRC` / `CRCError` | 帧校验错 | 光模块劣化、灰尘、线缆质量、电磁干扰 |
| `Input errors` | 输入错误总数 | 上面各种错误之和 |
| `Runts` | 超短帧 | 冲突、双工不匹配 |
| `Giants` | 超长帧 | MTU 不匹配、Jumbo 帧配置 |
| `Alignments` | 对齐错 | 物理层问题 |
| `Drops` / `Discard` | 丢弃 | 队列满、ACL 拒绝、QoS 丢包 |
| `Pause` | PFC 反压帧计数 | **智算排障核心指标** |

**判断方法**：连续两次 `display interface` 看计数**是否在增长**。不增长的历史错误可以忽略；持续增长必须查。

## 四、二层转发

```
display mac-address                        # MAC 表
display mac-address 0011-2233-4455         # 查某个 MAC 在哪
display mac-address aging-time             # 老化时间
display vlan                               # VLAN 信息
display port vlan                          # 接口 VLAN 配置
display stp brief                          # STP 端口状态与角色
display stp topology-change                # 拓扑变化次数（频繁变化=有环路/闪断）
display lldp neighbor brief                # LLDP 邻居（**最重要的拓扑发现工具**）
```

**LLDP 是现场利器**：不知道对端连的哪台设备哪个口时，`display lldp neighbor brief` 直接给出对端设备名和端口。割接前核对链路必用。

## 五、三层与路由

```
display ip routing-table                   # 路由表
display ip routing-table 10.1.1.1          # 查具体目的地址走哪
display ip routing-table protocol bgp      # 按协议过滤
display arp                                # ARP 表
display arp | include 10.1.1               # 查某个网段
display ip interface brief                 # 三层接口状态
display fib 10.1.1.1                       # FIB 表项（转发真正用的）
```

**路由表 vs FIB**：路由表是控制面（选路结果），FIB 是数据面（下驱动芯片）。**路由表有但 FIB 没有 = 转发不通**，这是排查"路由有但不通"的关键一步。

## 六、OSPF / BGP

```
# OSPF
display ospf peer                          # 邻居状态
display ospf peer brief
display ospf interface                     # 接口参数（cost/DR/定时器）
display ospf lsdb
display ospf routing
display ospf error                         # **错误统计，排障第一步**
display ospf brief

# BGP
display bgp peer
display bgp peer verbose                   # 定时器、能力协商
display bgp routing-table
display bgp routing-table 10.1.1.0         # 单条路由的属性
display bgp routing-table peer 1.1.1.1 advertised-routes
display bgp routing-table peer 1.1.1.1 received-routes
display bgp error
display tcp status                          # 看 179 连接
```

## 七、VXLAN / EVPN

```
display nve                                # NVE 接口与 VTEP 状态
display vxlan tunnel                       # 隧道列表（源/目的 VTEP）
display vxlan vni                          # VNI 配置
display bgp evpn routing-table             # EVPN 路由（按类型看）
display bgp evpn routing-table type 2      # 只看 MAC/IP 路由
display bridge-domain                      # BD 与 VNI 绑定
```

## 八、QoS / 无损

```
display qos queue statistics interface 400GE1/0/1   # 各队列收发/丢弃
display qos map-table                                # 映射表
display qos queue ecn                                # ECN 配置与统计
display priority-flow-control interface 400GE1/0/1   # PFC 状态与反压计数
display interface 400GE1/0/1 | include pause          # 快速看 pause 计数
display dcb                                           # DCB 全局状态
```

**PFC 排障核心**：

```
display interface 400GE1/0/1 | include "Pause|pause"
```

看 `Pause frames received` 是否快速增长。增长 = 这个口在上游方向上被反压了 = **对端发送太快或本端下游拥塞**。

## 十、日志与诊断

```
display logbuffer                  # 日志缓冲区（**排障第一入口**）
display logbuffer reverse          # 倒序看最近的
display trapbuffer                 # 告警
display health                     # 健康检查（华为特有的综合体检）
display diagnostic-information     # 一键收集所有诊断信息（提工单必附）
```

**`display diagnostic-information`** 会生成一个巨大的文本，包含所有 `display` 输出。提 TAC 工单时必须附这个，能省好几轮来回。

**日志等级**（看日志时判断严重性）：

| 等级 | 含义 |
|---|---|
| 0 Emergency | 系统不可用 |
| 1 Alert | 需要立即处理 |
| 2 Critical | 严重 |
| 3 Error | 错误 |
| 4 Warning | 警告 |
| 5 Notification | 通知（正常但重要，如接口 up/down） |
| 6 Informational | 信息 |

**接口 up/down 是 level 5**——所以查"接口闪断"要专门看 Notification 级别日志。

## 十一、常用运维操作

```
save                                  # 保存配置（改完必须 save，否则重启丢失）
reset counters interface 400GE1/0/1   # 清零接口计数（排障时先清零再看增长）
reset ospf process                     # 重启 OSPF（断邻居，慎用）
reset bgp all                          # 重置 BGP
refresh bgp all import                  # 软重置
undo / display this                    # 在配置视图里看当前层配置
```

**`display this`**：在任意配置视图下执行，只显示**当前视图的配置**，比重看整个配置快得多。现场改配置前先 `display this` 确认当前状态。

## 十二、现场排查的通用套路

**1. 分层排查（自下而上）**

```
物理层 → 数据链路层 → 网络层 → 应用层
光功率/接口状态 → MAC/ARP → 路由/FIB → 端口/策略
```

**2. 对比法**（最有效）

- 通的和不通的**两台设备**对比配置
- 同一台设备**两个方向**对比（A 到 B 通、B 到 A 不通 → 单向问题）
- **改之前和改之后**对比（`display current-configuration` 存档）

**3. 计数器法**

- 先 `reset counters` 清零
- 复现问题
- 看哪个计数器在涨 —— 计数器不会说谎

**4. 分段法**

- 从源头逐跳 ping/tracert
- 用 `ping -a 源地址` 指定源，避免"ping 通了但业务不通"（源地址不同走的路不同）

**5. MTU 排查**

```
ping -s 1472 -f 目标地址        # 不分片，1472+28 = 1500
```
不通说明路径 MTU 不足（VXLAN 场景必须测，因为封装多 50 字节）。

## 十三、几个容易踩的细节

| 细节 | 说明 |
|---|---|
| **`ping -a`** | 指定源地址。不指定时用出接口地址，可能和业务源地址不同 → 走不同路由 → 结论错误 |
| **`tracert -a`** | 同样要指定源 |
| **ICMP 被 CPU 代答** | 交换机对本机 IP 的 ICMP 可能由 CPU 回，**不代表转发路径通**。测转发要用业务流或 `ping` 非本机地址 |
| **ARP 学习限制** | 大二层场景 ARP 表可能被打满，需要调 `arp speed-limit` |
| **MAC 漂移** | 同一个 MAC 在两个口来回学 = 有环路或 M-LAG 双主 |
| **配置未保存** | `display saved-configuration` 对比 `display current-configuration`，重启会丢 |
| **时间不同步** | 日志时间错乱会导致排障时序完全错乱，先 `display clock` |
