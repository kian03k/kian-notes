# QoS 与优先级映射

> DSCP / 802.1p 的层级关系、PHB 与队列调度、WRED、限速，以及智算网络里的端到端标记规划。

## 一、为什么 QoS 本质是"排队规则"

网络拥塞时，报文必须在接口队列里排队。QoS 要回答三个问题：

1. **谁先走**（分类 + 调度）
2. **谁可以进来**（限速 + 丢弃）
3. **队列满了怎么办**（丢弃策略 / 标记）

**没有拥塞就没有 QoS**——链路利用率长期 30% 以下时，配 QoS 基本看不出效果。这是理解 QoS 的前提。

## 二、两个标记字段：802.1p 与 DSCP

### 802.1p（二层）

- 位于 **VLAN Tag 的 PCP 字段，3 bit，取值 0–7**
- 只存在于**带 Tag 的帧**里（Access 口收到无 Tag 帧就没有 802.1p）
- **出三层就丢失**（跨路由后 Tag 被剥掉）

| 值 | 名称 | 典型用途 |
|---|---|---|
| 7 | Network Control | 网络控制协议（STP、OSPF） |
| 6 | Internetwork Control | 路由协议（BGP） |
| 5 | Voice | 语音 |
| 4 | Video | 视频 |
| 3 | Critical | 关键业务 |
| 2 | — | — |
| 1 | Background | 后台 |
| 0 | Best Effort | 默认 |

### DSCP（三层）

- 位于 **IP 头的 ToS 字段高 6 bit，取值 0–63**
- **可以跨三层传递**（IP 头一直带着）
- 是端到端标记的正确选择

**DSCP 的命名体系**：

| 类别 | DSCP 值 | 含义 |
|---|---|---|
| **EF** | 46 | 加速转发（语音），低时延低抖动 |
| **AF41/42/43** | 34/36/38 | 保证转发，视频 |
| **AF31/32/33** | 26/28/30 | 保证转发，关键数据 |
| **AF21/22/23** | 18/20/22 | 保证转发 |
| **AF11/12/13** | 10/12/14 | 保证转发 |
| **CS7** | 56 | 网络控制 |
| **CS6** | 48 | 路由协议（**RoCE 常用 48**） |
| **CS0 / BE** | 0 | 默认尽力而为 |

**AF 的命名规则**：AFxy，x = 队列等级（1–4），y = 丢弃优先级（1–3），值越大丢弃概率越高。

**关键结论：三层组网用 DSCP，纯二层用 802.1p。** 智算网络是三层组网，所以用 DSCP（通常 RoCE 流量标 **DSCP 48 / CS6**，或者 26、24 等，看厂商模板）。

## 三、信任模式（Trust）

报文进入交换机时，交换机要决定"**信不信它自己带的优先级**"：

| 模式 | 行为 |
|---|---|
| **trust 802.1p** | 信任二层 Tag 的优先级 |
| **trust dscp** | 信任 IP 头的 DSCP（三层常用） |
| **untrust（默认）** | 不信，全部映射到默认优先级（通常 0） |
| **trust port** | 不看报文，直接按端口配的优先级打 |

**这里有个高频坑**：交换机默认 **untrust**，你配了 DSCP 但没配 `trust dscp`，结果是**所有流量都进了默认队列，PFC/ECN 全都不生效**。智算网络"配了 PFC 还是丢包"的第一排查项就是这个。

## 四、映射表（Map Table）

从报文标记到内部队列，要经过映射：

```
报文 802.1p/DSCP → [映射表] → 内部优先级（PHB）→ [队列映射] → 出端口队列
```

华为配置：

```
# 端口信任 DSCP
interface 400GE1/0/1
 trust dscp

# DSCP → 内部优先级（dscp-dscp 映射）
qos map-table dscp-dscp
 input 48 output 48
 input 46 output 46
 input 0  output 0

# 内部优先级 → 队列
qos map-table dot1p-dscp
```

**排障要点**：`display qos map-table` 能看到所有映射关系。**映射链路上任何一环配错，优先级就丢了**。

## 五、队列调度：PQ / WRR / DRR / WFQ

### PQ（Priority Queuing，严格优先级）

- 高优先级队列**只要有报文就一直发**，发完才轮到下一级
- **优点**：时延最低（语音、控制协议必备）
- **缺点**：低优先级队列可能**饿死**（一直发不出去）

### WRR（Weighted Round Robin，加权轮询）

- 按权重轮流发，每个队列保证一定带宽比例
- 缺点：**小包场景下按字节算权重会不公平**（需要按包数加权）

### DRR（Deficit Round Robin，差额轮询）

- WRR 的改进，用"赤字计数器"补偿变长包，更公平
- 华为默认常用 DRR

### WFQ（Weighted Fair Queuing，加权公平队列）

- 按流调度，保证每条流的公平性
- 计算量大，高性能交换机少用

**实战配置原则**：

- **控制协议（STP/BGP/OSPF）→ PQ 队列**，保证永不被业务挤掉（否则路由抖动）
- **语音/关键业务 → PQ 或高权重 WRR**
- **普通数据 → WRR/DRR**
- **BE → 低权重**

典型 8 队列方案（华为推荐）：

| 队列 | 用途 | 调度 |
|---|---|---|
| 7 | 控制协议（CS7/CS6） | PQ |
| 6 | 语音（EF） | PQ |
| 5 | 视频（AF4x） | WRR 20% |
| 4 | 关键数据（AF3x） | WRR 20% |
| 3 | **RoCE 无损队列** | WRR（但要保证不丢，靠 PFC/ECN） |
| 2 | 业务数据 | WRR 20% |
| 1 | 普通 | WRR 20% |
| 0 | BE | WRR 20% |

## 六、拥塞避免：RED / WRED

**问题**：队列满了才丢包（Tail Drop），会导致 **TCP 全局同步**——所有流同时丢包、同时降速、同时恢复，链路利用率剧烈震荡。

**RED（Random Early Detection）**：队列水位到阈值时**随机丢一部分包**，提前通知发送端降速。

**WRED（Weighted RED）**：按优先级区分丢包概率——高优先级流量丢得少，低优先级丢得多。

**三个阈值**：

- 低阈值以下：不丢
- 低–高阈值之间：按概率线性增长地丢
- 高阈值以上：全丢

**ECN 与 WRED 的关系**：ECN 就是 WRED 的"不丢包版本"——把"丢"换成"打 CE 标记"。所以 **ECN 配置本质上就是配 WRED 的阈值**。

## 七、流量监管与整形

### 监管（Policing / CAR）

- 超过速率**直接丢弃**或降级（重新标记）
- 用于**入口**，防止某条流占用过多带宽
- 令牌桶算法（单桶 / 双桶）

| 参数 | 含义 |
|---|---|
| **CIR**（承诺信息速率） | 允许的平均速率 |
| **CBS**（承诺突发尺寸） | 允许的突发量 |
| **PIR**（峰值信息速率） | 双桶时的最大速率 |
| **PBS** | 峰值突发尺寸 |

### 整形（Shaping）

- 超过速率**缓存起来慢慢发**（不丢）
- 用于**出口**，平滑流量
- 代价是增加时延和 buffer 占用

**一句话区分**：**监管是丢，整形是等。** 入口用监管，出口用整形。

## 八、智算网络的 QoS 规划（实战）

参数面的 QoS 要解决"**只给 RoCE 一个队列，且这个队列必须无损**"：

1. **打标**：服务器侧网卡给 RoCE 流量打 DSCP（通常 48 / CS6，或按厂商模板 26）
2. **信任**：交换机端口 `trust dscp`
3. **映射**：DSCP 48 → 内部优先级 6 → 队列 3（示例）
4. **无损**：队列 3 开 PFC + ECN
5. **其他流量**：业务/管理流量走其他队列，**绝对不能进无损队列**（否则它们也会触发 PFC 反压）

**为什么其他流量不能进无损队列**（面试点）：

PFC 是"队列级"的。如果业务流量混进无损队列，业务突发会把无损队列打满 → 触发 PFC → 反压 RoCE 流量 → **业务流量拖慢了训练**。所以**五平面分开的深层原因之一就是队列隔离**。

## 九、常见问题排查

| 现象 | 检查项 |
|---|---|
| 配了 QoS 没效果 | ① 端口 trust 模式对不对 ② map-table 映射是否正确 ③ 是否真拥塞（利用率太低看不出） |
| 语音卡顿 | 是否 PQ 队列；是否被低优先级流量挤占 |
| 控制协议震荡 | 控制协议是否在 PQ 队列；是否被业务抢占 |
| PFC 不生效 | trust dscp 是否配；DSCP→队列映射是否正确；队列是否 `qos queue x pfc` |
| 某类流量被饿死 | PQ 队列是否被高优先级长期占满；改用 WRR 或加限速 |
| 带宽跑不满 | 限速配错；WRED 阈值过低；ECN 过度标记 |

**命令**：

```
display qos queue statistics interface 400GE1/0/1    # 各队列收发统计
display qos map-table                                 # 映射表
display qos policy interface                          # 已应用的策略
display traffic-policy statistics interface xxx        # 限速统计
display interface 400GE1/0/1 | include pause           # PFC 反压计数
```
